# 语音总控跨项目调度

跨主机、跨项目的 Codex / Claude Code 调度统一由现有「语音总控」完成。不周山会话工具栏的「子 Agent」计数、右侧观察器和轮询入口移除，普通会话不再附加鼓励自动分工的应用提示。原生助手自身能力及项目工具中的既有原生读取功能保留；旧请求中的 nativeCollaboration 标志不再触发提示，Codex 下一轮显式清除旧 additionalContext。

## 查找、接管与派发

总控的 search 返回已接管和未接管会话，包含提供方、执行状态、是否可接管/开始/排队/追加，以及不可用原因。目标不明确时澄清，不按昵称猜测项目。读取会话不接管，不派任务。

明确授权使用指定未接管会话时，claim 通过已有 thread.claim 命令链路执行，要求会话空闲且可接管，并使用稳定幂等标识。总控读取 commandId 回执，只有原生命令成功、claimed 证据以及当前接管状态和原生线程一致才能认定成功。发出请求不是接管成功，接管成功也不是任务开始。保持接管沿用现有管理策略，不自动取消用户原有接管，不承诺任务结束后自动释放。

新任务先保存待办，再在当前执行授权下派发。空闲已接管会话使用 turn.start；忙碌的已接管会话可显式 mode:queue，使用现有 turn.queue 等待下一轮。Codex 的本轮补充可用 steer；当前 Claude 适配不支持 steer，须说明下一轮排队的区别。外部原生任务运行、离线或状态不明时不强行接管，不把恢复历史当作再次执行授权。

## 并发与结果

不同主机/不同工作目录可以并行。同一主机、同一实际项目目录的 Codex/Claude 使用共同冲突判断：已有面板任务保留、外部执行、未知状态和实时语音均需核验。检查在已有事务内完成，Windows 规范化路径；不同 worktree 保持独立。队列可以接收未来任务，但激活时再次核验目录冲突。

每个任务通过自己的 commandId/jobId/nativeTurnId 关联结果。排队任务不能使用该会话当前运行轮次的回复冒充结果。语音面板和服务端待办记录显示提供方与排队状态；排队不计入正在执行数量。重连只恢复记录，已提交任务不重复派发，通话结束不取消已派发任务。

## 版本与验证

语音主机需连接服务 0.30.98 才能获得新的 claim/queue 工具定义和指示。面板移除入口在刷新后生效；既有通话不强制刷新或重启。控制面 schema 56 取消每会话只能有一个非终态语音 job 的旧索引，执行互斥继续由命令和目录保留机制负责。

回归覆盖接管授权和原生回执、未知结果幂等、跨通话排队重试、任务结果归属、Claude 能力、跨提供方目录互斥及前端排队展示。模拟协议测试不等于真实麦克风端到端通话测试。发布必须走 voice-safe publisher，等待现有通话自然结束。
