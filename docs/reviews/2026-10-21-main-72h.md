### F1 · P1：Agent 重启后会丢失已确认的 Cursor 辅助进程归属

- **引入位置：** `e4e9a49`；[acp-providers.ts:99](/root/agentfleets/apps/local-agent/src/acp-providers.ts:99)、[acp-runtime.ts:222](/root/agentfleets/apps/local-agent/src/acp-runtime.ts:222)。已发布路径。
- **触发条件：** Cursor 一轮完成，Agent 已确认某个 `worker-server` 是自身 ACP 子进程并允许它继续存活；随后 Agent 重启，而辅助进程仍然存活。
- **根因：** 归属证据仅存入模块内的 `WeakMap`。源码明确允许这些辅助进程在 ACP 父进程退出后继续存在，但没有跨重启恢复这份证据。新运行时会把相同进程重新识别为外部原生进程。
- **证据：** 使用未修改的编译模块，在两个独立 VM 模块实例中提供相同的模拟进程表和启动标识。第一次保留归属后检查通过；重新加载模块后返回 `PROVIDER_NATIVE_BUSY`。没有启动真实或假 Cursor 进程，仅进行了 PID 存在性的 signal-0 检查。
- **影响：** 满足上述条件时，Cursor 面板发送可再次被阻塞。是否进一步阻塞同目录其他 provider，取决于目录发现和锁状态，本轮未复现，不能直接断言所有会话都会冻结。
- **建议：** 持久保存严格的进程归属证据，包括启动标识、可执行文件身份、原父进程和关联会话；恢复时逐项校验。或在原生明确支持的前提下完成辅助进程回收。不能仅凭名称、参数或 PID 放行，更不能清空所有占用保护。
- **验证补项：** “完成一轮 → 辅助进程存活 → Agent 更新/重启 → 原会话续发”，同时覆盖 PID 复用和真正外部 Cursor 进程仍被阻止。

证据：[reproduce-cursor-restart.json](/root/agentfleets/output/reviews/2026-10-21/reproduce-cursor-restart.json)。这是重启边界的模拟验证，没有实际重启生产 Agent。

### F2 · P1：工作树写操作未接入安全重启与结果不确定保护

- **引入提交：** `a0a3d63`。Agent 0.30.140 待发布路径。
- **位置：** [store.ts:705](/root/agentfleets/apps/local-agent/src/store.ts:705)、[maintenance.ts:55](/root/agentfleets/apps/local-agent/src/maintenance.ts:55)、[maintenance.ts:89](/root/agentfleets/apps/local-agent/src/maintenance.ts:89)、[cli.ts:323](/root/agentfleets/apps/local-agent/src/cli.ts:323)。
- **根因：** `canSafelyRestart()` 检查的维护类型没有工作树创建、合并或删除；这些操作也没有登记辅助活动。恢复逻辑中“已启动但结果未知，不自动重试”的分支同样遗漏 `worktree.*`，会重新调用原操作。
- **证据：** 临时状态库写入一个尚未过期、状态为 running 的 `worktree.merge` 后，`canSafelyRestart()` 返回 `true`；调用维护恢复，模拟的 `manageWorktree` 被调用一次并报告 succeeded。
- **影响：** 自动更新可能中断 Git 操作或最长 15 分钟的环境安装。若实际执行成功但回执未保存，恢复后可能再次操作已经变化的分支；接入已有工作树的环境脚本也可能重复运行。普通新建工作树可能只报“分支已存在”，同样无法正确恢复原操作结果。
- **建议：** 把工作树操作纳入活动保护；持久记录操作阶段、源/目标提交和已产生的结果。恢复优先核验事实，不能对未知写结果直接重放；确需重试时必须具有可证明的幂等前置条件。
- **验证补项：** 在 Git 成功与回执持久化之间模拟崩溃，重启后不重复合并、不重复运行 setup，并阻止操作期间升级重启。

证据：[reproduce-maintenance.json](/root/agentfleets/output/reviews/2026-10-21/reproduce-maintenance.json)。没有制造真实进程崩溃或执行生产合并。

### F4 · P2：未暂存文件名丢首字符，文件重叠检测漏报

- **引入提交：** `a0a3d63`。Agent 0.30.140 待发布路径。
- **位置：** [worktrees.ts:30](/root/agentfleets/apps/local-agent/src/worktrees.ts:30)、[worktrees.ts:90](/root/agentfleets/apps/local-agent/src/worktrees.ts:90)。
- **根因：** 对 porcelain 状态行先 `trim()` 再 `slice(3)`，破坏了 Git 的两列状态及分隔空格。
- **复现：** A 工作树未暂存修改 `shared.txt`，B 工作树暂存修改同名文件；返回文件名分别是 `hared.txt` 和 `shared.txt`，`overlaps` 是空数组。
- **影响：** 多智能体改动相同文件时漏掉提示；也可能把不同首字母的文件误合为一个。Git 自身的合并冲突检查仍存在，不能把此问题描述成 Git 一定会错误合并。
- **建议：** 使用 `git status --porcelain=v1 -z` 并按协议解析，保留空白、Unicode、重命名双路径；补暂存/未暂存混合场景测试。

- F1：将已释放 Cursor 辅助进程的 PID、启动身份和完整命令行保存到主机状态库；连接服务重建后重新验证，未知进程、PID 复用和命令变化仍阻止写入。
- F2：工作树创建、合并、删除均阻止自动升级；重启遇到未确认记录只报告需核验，不再次执行。终态工作树回执保留以防迟到投递重放。维护准入与自动升级使用同一个状态事务。
- F3：合并/删除前核验 Git 注册目录、共享 Git 目录及当前检出分支；偏离保存的身份时拒绝操作。
- F4：文件重叠判断使用 NUL 分隔的 Git 状态和文件列表，保留前导空格、中文以及重命名前后路径。
- F5：放弃未提交内容不再隐含强删分支；只有分支提交已进入主目录 HEAD 才尝试安全删除，否则保留分支。
- F6：初始化脚本失败后保留已创建工作树，显示失败输出，停止自动创建/打开会话。
- F9：控制面接受 Windows/UNC/POSIX 绝对路径，主机仍按本机路径和 Git 注册记录核验；网页项目查询支持 Windows 目录分隔符。
- 并发风险 1：工作树维护与命令预约按目录原子互斥，覆盖同目录不同 provider；同仓库 Git 管理操作串行，其他目录任务继续执行。原生终端在检查后主动写入仍不受面板锁控制，不能宣称覆盖外部并发。

F7、F8（SSH）和概览扫描性能风险留在本报告，未混入此次工作树发布。验证使用临时 Git 仓库、临时 SQLite 和模拟进程快照，不启动假原生智能体进程，不向真实会话发送测试任务。
