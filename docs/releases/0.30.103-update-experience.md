# Update experience — Agent 0.30.103

Updates prepare in the background and acquire exclusive maintenance admission only immediately before switching. Managed Codex preparation is persisted, bound to the exact target and current runtime configuration, and rechecks the artifact digests before activation. Cleanup retains the prepared candidate.

Agent and Codex discovery are independent; an Agent failure allows Codex preparation but not a second activation. Unsupported protocols still fail compatibility checks. The runtime target is re-read before activation so a withdrawn target is not installed.

Authenticated heartbeat acknowledgements carry a release revision hint. Changed hints coalesce into a verified manifest check with jitter and a minimum interval; normal polling remains the fallback. Download retries cover transient transport errors, HTTP 429 and 5xx. Integrity and schema failures do not retry. The central validator backs off transient checks from one minute to thirty minutes, retaining its existing six-hour schedule for other outcomes.

Terminal health receipts take priority over late activation progress. A running target without its receipt is shown as pending verification, not as a successful upgrade. This does not fabricate health evidence for past installs.

Settings → Updates shows panel build (administrators), published Agent, managed Codex target, last reported host versions and update progress. Manual checks use idempotency keys and disable duplicate submissions. Offline hosts cannot be updated through the view.

Existing rollout percentages/platform scopes and automatic-update opt-in remain unchanged. A new per-host pilot-selection UI, automatic cohort expansion, scheduled livestream windows, and independently served frontend releases are not part of this release. These need separate policy and deployment work; no live host is automatically selected as a pilot.

## Validation

- Control plane: 289 passing tests.
- Agent: 373 passing, eight platform-dependent skips on Linux.
- Web: 668 passing tests with NODE_ENV=test.
- Deployment guard: nine passing tests, including an active-call deferral and optional idle-validator deployment.
- Type checks and production builds; synthetic browser preview, no real host commands or user sessions dispatched.
- Four platform packages are built; macOS and Windows runtime execution is not verified by Linux tests.

## Deployment

Use the guarded publisher with an immutable prepared image. `--with-validator` includes the validation worker and defers if its reported phase is checking, downloading or validating. Existing call protection still applies; the option does not close calls or change rollout policy. Verify worker health and image after deployment as well as the public manifest and panel build.

The npm installer wrapper is unchanged. Hosts must receive Agent 0.30.103 before using its preparation/cache and hint handling. Already busy hosts keep the current process until the existing update policy allows a safe switch.
