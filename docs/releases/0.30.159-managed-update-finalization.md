# Agent 0.30.159 — managed update finalization and Windows CI

Managed provider updates could publish success before their cleanup and maintenance
admission release finished. An immediate next update then failed with
`PROVIDER_UPDATE_BUSY`, despite the previous operation already appearing complete.
Success and failure are now published after cleanup. A subsequent request joins a
terminal worker's final promise and rechecks shutdown and revision before admission;
updates that are still running remain blocked.

A deterministic regression test holds cleanup open, verifies that the update stays
active and rejects concurrent installation, then submits the next confirmed update
directly from the success notification. It verifies both activations and release of
maintenance admission. The related update/installation tests total 44 passing cases.

The Windows installation recovery fixture now supplies its per-installation
`bin/current.txt` pointer instead of assuming a POSIX launcher symlink. The existing
checks still preserve unknown receipts and block active tasks or voice calls, and
also verify the retained previous release. The Windows lifecycle job passed in
GitHub Actions after this fixture correction.
