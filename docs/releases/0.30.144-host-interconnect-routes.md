# 主机互通：连接方式、macOS 与互通矩阵（0.30.144，已发布）

把「SSH 互通」扩展为「主机互通」的第一阶段（路线：加固 → 泛化 → 面板中转）。

- **macOS 主机**可作为 SSH 账号的目标和发起方：用 `dscl` 查用户与家目录，探测 sshd 是否在监听（远程登录未开启时给出提示）。Windows 仍不支持。
- **连接方式**：直连或经跳板机（`ProxyJump`）。跳板机必须有直连账号，禁止多级；跳板账号对某源主机不可用时，该主机不会拿到依赖它的账号，不会静默改为直连。能力位 `sshRoutes` 保证旧版连接服务不会收到自己无法执行的账号。
- **候选地址类型**：自检把地址标为局域网 / 公网 / 虚拟网络（按网卡名与 100.64.0.0/10 等地址段识别 Tailscale、WireGuard、ZeroTier），编辑时可选择填入。面板不管理隧道。
- **互通矩阵**：`GET /api/ssh-links` 与「主机 → 主机互通」里的矩阵，状态来自真实测试并持久化（迁移 69：`host_ssh_accounts.route/proxy_jump_machine_id`、`host_ssh_link_tests`）；同步下发与矩阵共用同一份「计划」，说明未下发的原因。
- 界面：「SSH 互通」更名「主机互通」；测试、核验按钮仅管理员可见（与 0.30.143 服务端限制一致）。

验证：控制面 `ssh-access` 19 项 + 路由 3 项，本地代理 `ssh-access` 10 项，网页 `host-ssh-access` 9 项；迁移测试覆盖 68→69 升级、重复升级与既有账号保持直连。用本机真实 OpenSSH 做了端到端：生成配置后经跳板连接目标成功，停掉跳板机后目标不可达，证明确实经由跳板。

未验证：macOS 真机（目前只有用假 `dscl` 的单元测试）；需要用户在界面为 macOS 主机登记账号后核对自检结果与监听提示。

后续：阶段 2 面板 SSH 字节流中转（`auto` / `relay` 路由）。

发布说明：面板构建 `6efa446`，迁移 69 已在线上数据库应用（备份在发布前自动生成）；公网四个平台安装包按清单校验通过，旧版本产物校验和汇总不变（104 → 108 个安装包）。主机在空闲时自动升级到 0.30.144，升级前不具备本阶段的主机端能力（macOS、跳板、地址类型、监听探测）；面板侧的矩阵与路由校验已生效。

**镜像层数**：逐版本叠加会使面板镜像逼近 overlay 的层数上限（本次基础镜像已有 126 层，构建报 `max depth exceeded`）。做法是把当前线上镜像压平为新的基础镜像（`FROM scratch` + `COPY --from=<线上镜像> / /`，并显式写回 `ENV/USER/WORKDIR/ENTRYPOINT/CMD/HEALTHCHECK`），再照常叠加。压平后与原镜像逐项比对：17,554 个条目的路径、类型、大小、权限、属主一致，12,500 个文件内容逐字节一致，仅 `/etc/hostname`、`/etc/hosts`（Docker 每次启动注入）与下载目录自身的目录块大小不同。当前线上镜像只有 16 层，约可再叠加 7 个版本，之后需要再压平一次。
