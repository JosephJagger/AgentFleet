# Agent 0.30.157 — reconnect to the existing native Codex daemon

Codex can keep a native session loaded after its terminal closes. On the affected
host, Codex 0.165.0 publishes its process identity in
`app-server-daemon/daemon.pid`, while AgentFleets only inspected `app-server.pid`.
The existing shared-daemon fallback therefore could not find the legitimate writer
and returned `THREAD_WRITER_BUSY` when resuming that same session.

Discovery now prefers the native `daemon.pid` and supports the older expected name
only when the native file is absent. Invalid identities, ownership, permissions,
process generations, socket listeners and mismatched thread locks still fail closed.
The existing fallback attaches only after an explicit writer refusal and verifies
native permissions and activity before accepting a task. It neither deletes locks,
stops native clients, nor automatically replays a failed task.

Validation: local-agent TypeScript build and 32 targeted transport/session tests,
including isolated Codex 0.165.0 integration tests without credentials or model
requests. These verify same-thread attachment, unchanged permissions, refusal of
conflicting permissions, and preservation of the daemon and its original client
after panel detachment. A read-only probe on the affected host also discovered the
actual daemon, connected and read the original thread without starting a turn.
