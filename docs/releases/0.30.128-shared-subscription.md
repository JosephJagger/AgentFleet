# Cursor / Grok shared subscription allowance (0.30.128, published; superseded by 0.30.129)

Both provider views can display the same native Grok billing allowance after the host verifies the account relationship. Session token totals remain provider/session scoped. No Grok session usage is copied into Cursor, no percentage is converted into session tokens, and no account balance is editable.

## Identity and refresh

The Grok discovery read still uses `_x.ai/billing` at most every two minutes. Only `isUnifiedBillingUser: true` qualifies for verification. An authenticated read to Grok's OIDC `https://auth.x.ai/oauth2/userinfo` must return the same subject as Cursor's native `https://api2.cursor.sh/aiserver.v1.DashboardService/GetSandMarketingIdentity` unified workspace `externalId`, and match the selected local Grok OAuth User principal. There is no email, display-name or machine-name matching. The native credential snapshot is taken before opening the billing connection and rechecked around identity reads; a credential change invalidates the attempt. Credentials and raw identity values stay on the host and are never logged or sent to the panel.

Cursor auth-file paths follow native AuthStorage: Linux XDG config (default `~/.config/cursor/auth.json`), macOS `~/.cursor/auth.json`, Windows AppData/Roaming/Cursor/auth.json. `CURSOR_CONFIG_DIR` controls other native data, not this auth file. Grok uses its GROK_HOME auth file and the known official OAuth client. Custom API/auth-token environments, unsupported principals, missing credentials, mismatched/legacy workspaces, failures or unrecognized responses leave sharing unavailable. This deliberately does not promise support for every enterprise/custom authentication setup.

The association contains only source and verification/expiry timestamps. Maximum lifetime is three minutes, validated at ingress and again on quota reads. Failed billing/identity refresh removes the association; the independent timestamped Grok snapshot may remain. Cursor does not reuse an expired association. The UI also expires the display locally if a refresh hangs. Updates are discovery snapshots, not instantaneous account-switch push notifications; an account change between checks can remain visible until the bounded expiry. Browser usage refresh is every thirty seconds while active.

The Cursor and Grok allowance surfaces label the shared native source, source host, reset time and observation time. No cross-host summation is added. Other providers and native execution/approval paths are unchanged.

## Validation and limits

Read-only checks on B52H confirmed that the actual services return matching account identities and a unified workspace. Grok native billing reported 4% used, with the weekly period ending 2026-10-24T14:46:08.776Z. No model prompt, account setting change or task takeover was performed.

Targeted tests cover identity mismatch, legacy plan, API credentials, network/logout/change races, platform auth paths, account-proof expiry, source labeling and isolation of provider/session tokens. Local agent/ACP: 50 passed; control-plane usage: 20 passed; web Cursor/usage: 26 passed. All three applications built successfully. Existing web large-chunk advisory remains. Browser preview at 390×844 and 1440×1000 used production components with a synthetic quota snapshot; mobile dialog had no horizontal overflow. Preview only reported favicon 404 and was removed after verification.

The native Cursor dashboard RPC is an installed-client interface, not a separately guaranteed public API. Changes fail closed. Native account matching was tested on Linux; macOS/Windows auth-path logic has unit coverage but was not tested against live accounts. This work does not add Cursor per-turn cost retrieval or Grok cost-history UI.

Implementation version is 0.30.128. Not committed, published, or installed as part of this development turn. Requires the new control plane/web and a host running this Agent version. Existing guarded deployment and normal idle host-update conditions apply; no voice/task interruption is authorized by this implementation.

Superseded by 0.30.129 (`0.30.129-cursor-account-quota.md`): Cursor allowance is now read from Cursor's own account service and this identity-matching design was removed. Hosts still on 0.30.128 report the old association, which the current control plane ignores, so they show no Cursor allowance until updated.
