# Cursor account allowance from Cursor's own account service (0.30.129, published)

Cursor's allowance is read from Cursor's own account service for the account the host is logged in with. It no longer borrows Grok's billing numbers, so it stays correct when Cursor and Grok are signed in with different accounts. This replaces the identity-matching design shipped in 0.30.128 (`0.30.128-shared-subscription.md`), which is removed (no `shared-subscription`, no `sharedSubscription` field, no Grok credential fingerprint).

## Why not ACP

`agent acp` registers only seven `cursor/*` extension methods (`canvas`, `update_todos`, `task`, `list_available_models`, `generate_image`, `create_plan`, `ask_question`). None reports usage or allowance, and `agent about` shows only the plan tier. The CLI's own account views use `aiserver.v1.DashboardService` on `api2.cursor.sh`.

## What is read

At most every two minutes, in the same discovery pass that already refreshes the Cursor model list, the host calls two read-only methods with the logged-in Cursor access token:

- `GetCurrentPeriodUsage`: `planUsage.totalPercentUsed` and the period `billingCycleStart` / `billingCycleEnd` (a 7-day window on the Super plan).
- `GetPlanInfo`: `planName`, and `includedUsageResetsAt` (used as the reset time when it agrees with the period end).

Only the used percentage, the actual window, the reset time and the plan name are kept (`bucket: "cursor"`). Tokens, spend, grants and free-text messages are never stored or forwarded. The control plane re-validates the snapshot (percentage 0–100, sane window) before showing it.

## Fail-closed behaviour

- No Cursor quota when the host uses a custom key or endpoint (`CURSOR_API_KEY`, `CURSOR_AUTH_TOKEN`, `CURSOR_API_ENDPOINT`, `CURSOR_API_BASE_URL`, `CURSOR_WEBSITE_URL`), is logged out, or the service answers 401/403: the displayed quota is removed rather than guessed.
- Network errors, 5xx and unrecognised responses keep the previous timestamped observation; it is marked out of date after three minutes. Failure is never shown as zero or 100%.
- If the auth file's access token changes while a request is in flight (account switch), that result is discarded.

Auth-file paths follow native storage: Linux XDG config (default `~/.config/cursor/auth.json`), macOS `~/.cursor/auth.json`, Windows `%APPDATA%/Cursor/auth.json`. `CURSOR_CONFIG_DIR` controls other native data, not this file.

## Sessions (finding, unchanged)

ACP `session/list` only enumerates sessions stored under `<cursor config>/acp-sessions`. Terminal chats live under `chats/` and are invisible to it, so the existing verified-storage scan plus bridge remains necessary.

## Validation and limits

Verified against the real service on Linux: 4.6% used, 95.4% remaining, 7-day window, plan Super. Unit tests cover parsing, malformed or out-of-range reports, overrides, logout, 401, transient failures and the account-switch race; control-plane tests cover the Cursor/Grok separation; web tests cover display, stale marking and the missing-quota message.

The dashboard RPCs are an installed-client interface, not a documented public API, and may change; changes fail closed. macOS/Windows auth-path logic has unit coverage but was not tested against live accounts.

Published together with the control plane/web change (build `c13cafb`); public installers for all four platforms were verified against the manifest. Hosts update under the normal idle conditions. Until a host runs 0.30.129 it shows no Cursor allowance (0.30.128 hosts still report the old association, which is ignored).
