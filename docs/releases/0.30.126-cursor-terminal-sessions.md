# Agent 0.30.126 — Cursor terminal discovery and continuation

Cursor 2026.10.16-e3cb207 keeps interactive CLI conversations in
`<config>/chats/<bucket>/<uuid>/store.db`. Its ACP `session/list` and
`session/load` only inspect `<config>/acp-sessions/<uuid>`. Consequently,
correctly detecting the installed CLI did not make terminal conversations
available in AgentFleet. B52H also has both ~/.cursor and an XDG config root;
using only the service's default profile can miss terminal-created records.

Discovery reads bounded schema-1 CLI sidecars, preserving native UUID and cwd,
excluding empty/subagent/invalid records. Explicit CURSOR_CONFIG_DIR takes
precedence; otherwise the current XDG root and ~/.cursor are scanned. Duplicate
UUIDs in different stores are rejected. Discovery creates no aliases or tasks.

Before takeover, the existing external-writer guard runs and metadata is read
again. The verified native SQLite meta/blob schema, agentId and root blob must
match. A separate ACP sidecar and a file symlink to the **same original store**
are then atomically installed under acp-sessions. There is no database copy,
SQL mutation, context re-creation, shell PATH edit or credential copy. Cursor
itself loads and writes the store through ACP; the original CLI sidecar is not
linked because ACP rewrites its different metadata schema. Existing unrelated
ACP stores and conflicting aliases are never overwritten. AgentFleet-owned
alias metadata identifies its original store and is revalidated on reuse.

This is a version-gated storage compatibility adapter, not an upstream promise
that CLI and ACP directories are interchangeable. It permits terminal takeover
only for 2026.10.16-e3cb207 on POSIX. Windows terminal-store bridging and other
versions are explicitly rejected until verified; their existing ACP sessions
remain supported. Symlink creation failure is surfaced without a copy fallback.
The alias persists for native ACP discovery; deleting it does not delete the
original CLI database. Normal takeover is still required before sending tasks.

Cursor's bundled Node and SEA processes now count as external writers. Children
of the panel's own live ACP process are recognized as owned, avoiding false busy
errors. Other Cursor terminals remain conservatively exclusive host-wide; this
release does not allow simultaneous terminal/panel writers or running-turn append.

Validation:
- Targeted catalog/runtime tests cover empty and malformed metadata, explicit/XDG
  paths, duplicate IDs, unsupported versions, identity/cwd changes, conflicting
  native stores, exact shared-store writes, ownership, history and continuation.
- B52H Linux live isolated test used native session
  59538be9-6626-4e2d-89ac-174acde701f5 in /tmp/agentfleet-cursor-resume-check.
  Native CLI created context; ACP replayed history through the actual Fleet
  runtime, accepted a new turn and produced completion events. Native CLI then
  resumed the identical ID and returned the marker added by the panel turn.
- User's Test Run session was found by read-only discovery only. No task or
  takeover was performed on it. No existing CLI was stopped for testing.
- No new browser component: existing ACP approval, streaming, image input,
  cancellation, queue and history UI are reused. No new live browser or image/
  approval scenario is claimed by the real native continuation probe.

Deployment must use the guarded publisher and a fresh immutable Agent artifact.
Hosts adopt 0.30.126 only when the existing safe-update checks permit it; there is
no forced host restart. Catalog discovery runs on the existing approximately
60-second cadence after host activation. Until activation, web refresh alone
cannot enable the new discovery path. Native storage compatibility must be
revalidated before widening the accepted Cursor version.
