# 0.30.106 — Voice transcript call/time browsing

The previous tool required a nonempty keyword and recognized retrieval/renewed authorization through a small set of sentence prefixes. After reading history, new requirement descriptions that did not match those prefixes left the call read-only, blocking `todo.save` as well as execution. Existing request/response transcript evidence corroborated that failure path; this change does not claim that every vague description constitutes authorization.

`transcript.search` now accepts optional `query`, `recentCalls` (1–100), `relativeDays` (1–30), `startAt`/`endAt` (ISO datetime with timezone), `includeCurrent` (default true), and a scoped `cursor`. Examples: latest three calls = recentCalls 3; last day/week = rolling relativeDays 1/7. Calendar requests such as yesterday require explicit timezone boundaries; the coordinator must clarify ambiguous timezone. Relative and explicit date ranges cannot be mixed. The start is inclusive and end exclusive. Time selection uses each utterance's first observed timestamp.

With no keyword/range, only the latest retained call is read. Latest-N calls are selected before keyword filtering, so an absent keyword never expands the search to older calls. Only calls containing retained records in the selected period count. Time-only and keyword-only queries select at most 100 calls and explicitly flag excess; narrow the time range to inspect more. Current call is included unless excluded. Calls sort newest first; both roles within a call sort by original utterance sequence. Returned `groups` and compatible flat `items` preserve call IDs, role, time, source and partial flags. Pages contain at most 20 fragments with a conservative text budget. Without keywords, utterances longer than 4,000 characters continue across pages rather than being lost. Keyword searches return bounded matching excerpts, not entire call context; remove keywords to browse all utterances in that call/time range.

The cursor binds account, workspace, requesting call and filters; the call selection and maximum row ID are pinned across pages, excluding newly inserted rows. Existing incomplete utterances may still be updated, and records can expire during paging: this is not a frozen transcript export. Keep filters unchanged for nextCursor. A later fresh query includes new arrivals. No whole-history automatic loading is added. Search remains off by default and account/workspace scoped; it must be enabled and requested through fresh final native user speech. Authorization lasts two minutes and a natural continuation such as “继续查看” renews retrieval. Replay, assistant/tool/history text and partial speech never authorize retrieval or release writes.

Natural request recognition now accepts phrases such as “然后你查下转写”, “看看最近三次通话”, “我们最近三次通话都聊了什么”, and “给我最近两次通话转写”. It remains conservative rule-based recognition, not an unrestricted semantic authorization classifier. Unclear wording should trigger one short clarification, never a promised save without receipt. A fresh explicit save request enables only `todo.save`; dispatch/claim/steer remain blocked until a separate explicit execution request. Questions about a failed save, hypotheticals, negative requests and quoted instructions do not unlock execution. No boolean tool argument can create this native-user authorization. Existing command permissions and idempotency stay in place.

Storage remains 30 days for uploaded user and assistant text in this account/workspace, independent of the search switch. No schema or retention migration; existing rows are reused. No unrecognized audio, lost/unuploaded text or expired rows can be reconstructed. Historical records remain untrusted data and never auto-create/execute tasks.

The existing checkbox/help UI now explains keyword-free call/time browsing and saving versus executing, rather than prescribing a fixed search phrase. No extra toolbar button or automatic history browser was added. Backend changes apply after safe publication; new tool parameters and prompt guidance need voice host Agent 0.30.106 and a naturally started new call. Existing calls are never forced to restart. Synthetic tests verify storage/query/authorization/pagination behavior, not real-world speech recognition accuracy.
