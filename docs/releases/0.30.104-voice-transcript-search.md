# Voice transcript storage and opt-in search — Agent 0.30.104

## User behavior

The voice coordinator replaces “待确认转写” and its review/save/discard flow with “支持搜索转写”. The checkbox defaults off and is stored per signed-in account within a workspace, independently of project content retention and takeover policy. Saving the checkbox uses existing authenticated, CSRF-protected routes, optimistic revision checks and audit entries. The server checks permission on every search; changing the setting invalidates outstanding search grants immediately.

Uploaded recognized coordinator speech from both user and assistant is stored for 30 rolling days whether search is on or off. It records call ID, role, utterance ID, original observation time, first sequence, last sequence and completeness. The periodic voice maintenance path prunes expired rows; search additionally prunes/filters at the exact retention boundary. No audio is stored by this feature. Session-level voice and project history remain separate sources.

With the checkbox on, say “搜索通话转写中的发布” (or another literal keyword). A fresh, final recognized search request enables bounded retrieval for two minutes in that call. Merely enabling the setting, reconnecting, assistant speech, replayed transcripts, or tool arguments cannot create a grant. Conservative Chinese/English command forms are recognized; ambiguous or unsupported phrasing must be repeated explicitly rather than silently authorized. Queries require a literal keyword (1–200 characters), return at most 20 records per page, and expose truncation beyond 4,000 characters. Results include call, role, time, order and incomplete/legacy-source labels. They are untrusted evidence and are not automatically loaded at call startup. Search never creates a todo or dispatches work. After retrieval, write tools remain blocked until a fresh explicit user action instruction; an acknowledgment such as “嗯” does not unlock them.

## Data flow and migration

Agent 0.30.104 assigns stable utterance IDs and a call-wide monotonic sequence to both transcript roles. Every recognized delta is sent as a cumulative snapshot. The server persists before acknowledging. The same live voice process retains unacknowledged snapshots and replays all of them, marked as replay, after existing identity/epoch recovery succeeds. Acknowledgments for an earlier sequence cannot discard newer text. This extends the existing recovery mechanism without starting a replacement call or weakening fencing.

Schema 60 migrates available old tail/draft snippets as `legacy_partial`, deduplicates a tail and its draft, then drops the review tables. Previously saved todos remain unchanged. The old review API and UI are removed. Existing absent, discarded, expired, never-recognized, and lost/unuploaded text cannot be reconstructed. The in-process replay buffer is not a durable recorder: a real process loss before upload can lose unacknowledged speech. Old Agents remain ingest-compatible, with `compat_partial` evidence, but cannot use the new search tool or guarantee full disconnect replay. Complete behavior requires Agent 0.30.104 and a new naturally started call after upgrade.

## Safety and delivery

No live call is restarted to enable the feature. Prepare immutable panel and Agent artifacts, then use `packaging/deploy-control-plane.py`. Active or uncertain global/session calls defer publication; never bypass the guard. Existing Agent binaries remain immutable; npm installer wrapper version is unchanged. Once safely published, reload the panel after ending the current call and let the voice host update under its normal update policy.

Schema 60 cannot be opened by older binaries. Rollback needs a compatible schema-60 binary or a properly reviewed pre-upgrade database restore, not simply retagging an old image. This branch is based on the existing development baseline; this task does not execute historical todos or modify native Codex configuration.

Validation uses synthetic calls and transcripts, never live microphone/production conversation data. Coverage includes permission/CSRF/conflict handling, cross-call retrieval and owner scope, snapshots/replay/deduplication, request expiry, storage with search disabled, write blocking, 30-day pruning, migration/persistence, and retired routes. Live audio recognition and a real network interruption are not simulated as successful production tests.
