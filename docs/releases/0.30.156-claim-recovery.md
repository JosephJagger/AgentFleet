# Agent 0.30.156 — claim history recovery and cloud image cleanup

Older agents could leave `thread.claim` unknown after `thread/items/list` timed out,
blocking both the session and automatic updates. Connection repair now recognizes
that exact history timeout, verifies idle writer release under maintenance drain,
and returns a negative terminal receipt without replaying a task or deleting history.
New claims that have already persisted their binding and released their writer retain
their history checkpoint and report pending history synchronization instead of an
unknown command when paging times out.

For affected older hosts, publish this release first, then use the panel's local
repair installation command under the original OS account while tasks and calls are
idle. The downloaded agent performs installation admission: this specific claim
timeout may pass, while active work and unknown task outcomes remain blocked. The
installer preserves the unknown receipt; after reconnection, use connection repair
to verify and settle it. Installing a previous release does not fix this case.

The panel also restores an explicitly confirmed, revision-checked cloud-only image
cleanup action for all host systems. It removes cloud image copies across the chosen
host's sessions; host originals, text and file attachments remain. macOS native
history image cleanup is still unsupported. No images are deleted by this release.

Validation: 134 related agent recovery/runtime/store tests, eight installation
lifecycle tests including installation admission from a legacy history timeout,
and the cloud image cleanup tests documented with the accompanying panel change.
These are targeted regressions, not a rerun of all three application test suites.
