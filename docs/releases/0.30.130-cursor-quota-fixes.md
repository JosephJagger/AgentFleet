# Cursor allowance reliability (0.30.130, pending publication)

This fixes the 0.30.129 review findings without changing task execution, permissions, session ownership or provider token accounting.

- Cursor native login/connection failure clears the allowance snapshot and its private credential generation; missing executable also clears it. The control plane independently suppresses snapshots reported by login-required, missing, error or unverified Cursor runtimes, including older hosts that retain a snapshot.
- Before an account query the host compares a SHA-256 credential-generation fingerprint held only in process memory. A changed credential clears the prior quota before the new request. Logout, custom auth and 401/403 clear it. Credentials and fingerprints are never returned as metadata or logged. Native token refresh also changes the fingerprint, conservatively discarding the old observation until a successful read.
- Same-credential transient account-query failures can keep the timestamped observation, marked stale by existing age/reset rules. Account changes during failed requests or immediately before return discard the result. Discovery still polls at most every two minutes; this is not instantaneous logout push notification.
- Optional GetPlanInfo network/JSON failures cannot mask GetCurrentPeriodUsage authentication or discard successful quota. No task, prompt or authentication mutation is performed. The existing five-second request deadline remains.
- Account percentages display at most one decimal place across session settings, usage dialogs and host/compact cards. Numeric values and CSS/progress measurements retain native precision.
- ACP tests inject the quota reader so synthetic provider fixtures do not read real login files or query real account services.
