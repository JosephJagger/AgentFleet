# Agent 0.30.125 — recognize Cursor calendar builds

Cursor 2026.10.16-e3cb207 is installed on B52H but its `--version` output has
no vendor name. The 0.30.124 detector skipped it even though it searched past
Grok's identically named `agent` executable. Changing PATH alone cannot repair
that false negative.

The detector now recognizes the bounded YYYY.MM.DD-commit version shape and
requires Cursor's read-only `acp --help` vendor/protocol identification before
accepting it. It launches the exact candidate path, not a bare PATH command.
Branded versions retain the existing checks. Ambiguous identities and failed
help probes remain rejected. No shell profile, login, credentials or native
CLI installation is changed.

Regression tests include the actual observed version/help format, Grok ahead of
Cursor, symlinks in separate PATH directories, a different vendor using a date
version, failed help and help missing vendor identity. These tests run in the
normal local-agent CI suite; POSIX shell/symlink fixtures run on Linux/macOS.
The parsing code is shared with Windows, but this release does not claim a live
Windows Cursor installation test.

Local live verification detected Cursor and Grok correctly with Grok first in
PATH. An isolated initialize-only ACP handshake returned protocolVersion 1 and
Cursor capabilities; no prompt, new session, project task or login was issued.
This proves discovery and protocol negotiation, not authenticated task execution.

Publication uses the voice guard and a new immutable Agent version. The host
must safely update to 0.30.125 before discovery changes. Active tasks, voice calls
and uncertain commands continue to defer host replacement. No forced restart.
