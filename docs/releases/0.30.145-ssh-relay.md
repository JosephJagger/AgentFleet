# 面板中转：主机之间连不通时经面板转发 SSH（0.30.145，已发布）

把「主机互通」的第三个路由做成：当两台主机无法直连（例如在 NAT 后面）时，SSH 字节流经面板转发。详见 `docs/host-ssh-access.md` 的「面板中转」。

- **默认关闭**，按工作区由平台管理员开启；账号可选「仅经面板中转」或「自动（直连优先）」。迁移 70：`host_ssh_settings`（开关与修订号）、`ssh_relay_streams`（流记录，供发布器识别）。
- **目标主机只连本机 sshd**，帧里没有地址与端口；SSH 端到端加密，面板看不到内容；必须先固定目标主机指纹。
- **断线续传**：两端保留带序号的未确认数据，WebSocket 断开 60 秒内重连即可无感续传。真实环境里主机连接平均 1–2 小时断一次，这是必须的。
- **发布器**会等待活动中的中转流（和语音通话一样），不会强行断开。
- 互通矩阵显示中转的真实状态，以及中转为何没有生效（开关未开、需更新连接服务、指纹未固定）。
- `ssh-proxy` 有独立精简入口，启动 0.04 秒（经主 CLI 要 0.27 秒）。

验证：流层 9 项（含反复断线零丢失、重复帧、流控、协议违规）、管理器 11 项（含真实子进程、断线续传、限额、转义序列）、控制面枢纽 15 项 + WebSocket 端到端 2 项、迁移 69→70、发布器 16 项、网页 15 项。对流层做过变异验证（去掉续传握手、去掉重传，对应测试都会失败）。**用真实的 OpenSSH 与 sshd 做了完整端到端**：真实控制面、真实代理代码，`ssh` 经 `ProxyCommand → 本机套接字 → WebSocket → 面板 → WebSocket → 目标代理 → sshd` 连通；`ssh` 确认指纹与固定的一致；长命令运行中途切断并恢复一端的 WebSocket，输出完整、退出码 0；三条流都以 `complete` 记录。

已知限制：未在真实的多主机、多网络环境验证（只验证了回环）；真实延迟下的吞吐按公式估算；中转经过面板域名，其服务条款（若有 CDN/代理）需使用者自行确认；面板重启会终止未续传的流（发布器会等待它们结束）；macOS 仍只有单元测试。

后续：为中转配置不经代理的独立域名；中转作为跳板的第一跳。

发布说明：面板构建 `69ff7e8-relay-20261022`，迁移 70 已在线上数据库应用；公网四个平台安装包按清单校验通过，旧版本产物校验和汇总不变（108 → 112 个安装包）。发布器 `--check` 现在会在数据库有 `ssh_relay_streams` 表后显示 `ssh_relay_streams` 计数。主机在空闲时自动升级到 0.30.145；升级前不具备中转能力，不会收到中转账号。

**部署注意（多会话）**：发布时另一个会话正在 `feat/work_tree` 工作树里改前端（工作区分页），并已把未提交的改动部署上线。直接从主分支部署会把线上前端回退。本次的做法是：以线上镜像为基础，用主分支的干净导出叠加那个工作树里 3 个未提交文件的只读副本构建网页，并核对新入口文件仍含它的改动。该会话下一次部署前需要先合并主分支，否则会覆盖本次的中转界面。
