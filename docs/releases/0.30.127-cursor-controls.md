# Cursor session controls (0.30.127, pending publication)

Cursor now has model, native model parameters, task mode and permission controls in **Session configuration**, with a compact composer shortcut. Available values come from the host Cursor account and the actual ACP session. Codex, Claude Code and Grok keep their existing settings paths.

## Behavior and scope

- Independent workspace/session preferences, authenticated GET and existing same-origin/CSRF protected PUT, revision conflicts and audit records. Saving does not dispatch a task or interrupt the running turn. New starts and queued tasks capture saved preferences through the existing command path. Previously queued tasks retain their captured settings.
- Agent 0.30.127 or newer is required. Older hosts can continue ordinary tasks; new controls show the update requirement and remain disabled.
- Cursor ACP uses `parameterizedModelPicker`, `cursor/list_available_models`, `configOptions` and `session/set_config_option`. Apply the model first, revalidate model-dependent options, and require the native response to confirm every selection before sending the prompt. No speculative model list, CLI flags, native config-file editing, PATH change or automatic command replay.
- Native catalog reads are bounded and throttled to two minutes. Browser preference reads are coalesced, checked every five seconds when session sequence changes, and refreshed at least every thirty seconds while the inspector is mounted. The configuration's **reload** button reads the latest server metadata; it does not launch a task.
- Latest claimed/created/completed-session configuration metadata survives conversation-body expiry in a separate metadata table (schema 65). It is a timestamped observation. Each actual start still checks the current native options. Soft-deleted sessions cannot read/write these rows; physical session deletion cascades to preference/option rows.
- Model switching through Cursor's own API also persists Cursor's host default selection. Other Fleet sessions with explicit saved models reapply those models before their next prompts; sessions that inherit native defaults follow Cursor's default behavior.
- Permission defaults to native approval, forwarded to the panel. The optional session allow mode selects only an offered `allow_once` for tool requests during that turn. It does not change global allowlists, bypass native sandbox/deny rules, or answer questions/approve plans. If one-time permission is unavailable, the normal approval path remains.
- Consumption and remaining quota are visible in the configuration. Consumption records only actual native token reports; flat per-turn reports accumulate without losing equal consecutive turns. No telemetry means **not reported**, never zero. The verified Cursor version provides no account-quota query, so remaining quota is explicitly unavailable. Context occupancy is not treated as billed usage. There is no fabricated editable account balance or quota limit.

## Verification

Verified installed Cursor `2026.10.16-e3cb207` in a temporary isolated config/workspace with copied login material, removed on completion. No user conversation was resumed and no model prompt was submitted:

- Native catalog returned 46 models and three modes (Agent/Plan/Ask).
- Native calls confirmed model `gpt-5.6-sol` and mode `plan`.
- Model-dependent options included `context` (272k/1m), `reasoning` (none through max), and `fast` (false/true).
- `cursor/list_available_models` is the actual wire method; `_cursor/list_available_models` returned method-not-found.
- Synthetic protocol tests cover model validation before prompt, actual option confirmation, independent permissions/reset, and consecutive token reports.
- Control-plane tests cover provider/workspace/session isolation, saved-state reopen, stale-write rejection, old-host rejection, discovery sanitization and saved preferences reaching the outgoing command content.
- React tests cover stale polling responses, refresh persistence, model-parameter reset and disabled old-host controls. Full workspace tests include Cursor image input without Codex settings injection.
- Isolated browser preview used the actual returned native options and production components/styles at 1440×1000 and 390×844. Model selection/save, dialog scrolling and usage access were checked. The preview's only console error was its missing favicon. Temporary preview source and server were removed.

Validation: control-plane 352 passed; web 795 passed; local-agent 503 passed and 10 conditional skips. The final ACP-targeted run passed all 46 tests after the final cross-option confirmation check. Type checks and all three application builds passed; the web build retains its existing large-chunk advisory. An initial concurrent run exposed a fixed missing mock in the workspace suite and a timing-sensitive pre-existing download-progress test; the corrected web suite and serial local-agent run passed. Validation logs and screenshots are in `/tmp/cursor-*`. Native/model integration was verified on Linux only. Real billed turn usage, account quota retrieval, Windows/macOS Cursor execution and a production-browser end-to-end task were not claimed.
