# 0.30.105 — Voice coordinator host/session directory

The coordinator now uses a shared directory API for authorized session discovery. Previously `search` passed the entire utterance to a single literal substring filter and ignored its machine/project parameters. A phrase combining a host, project and title could therefore return nothing even when each identity existed.

`GET /api/voice-directory` and coordinator actions `directory` / `search` share the same workspace-scoped implementation. Query tokens separated by whitespace are AND across identity fields; explicit `host`, `project`, `sessionName`, `machineId`, `projectId`, and `provider` filters also intersect. Providers are `codex` and `claude`. `directoryStatus` supports `all`, `active` (managed OR fresh running), `online`, `managed`, and `running`. `currentTask:true` selects only fresh running sessions and never falls back silently. Natural language should be decomposed into these filters by the coordinator, not sent verbatim as a literal phrase.

Online hosts are listed separately, including hosts with no sessions; only host filters apply to this list. Host summaries are capped at 50 with an explicit total/truncation marker; narrow by host if needed. Sessions are paged by stable identity, 20 per page, with filter/workspace-bound cursors. Pages are live projections, not a frozen snapshot. Queries read metadata and available-action hints, not conversation bodies. History and progress are fetched separately only when needed.

The voice popup includes a collapsed directory with status/provider filters, combined search and optional name fields. It refreshes every 15 seconds while expanded and visible, debounces edits by 300 ms, aborts obsolete requests and allows manual refresh. A failed refresh marks old results stale. Opening a session navigates only; it never takes over or dispatches work. Applies to all themes using the shared coordinator popup.

Entries expose exact session/machine/project IDs, provider, last reported execution state, active turn, managed state, source, query time, host heartbeat and session update time. `live` means online host with heartbeat within 90 seconds and live session projection; it does not prove a fresh native RPC was made. Stale records remain searchable globally but cannot become fresh running candidates. Multiple candidates require clarification. Host disconnect sweeps and current permissions remain authoritative.

Before NEW claim/steer/dispatch commands, the backend rechecks host identity, heartbeat and session reachability as well as existing permissions, writer exclusion, control/turn versions and native receipt rules. Existing duplicate requests still return their prior receipt rather than starting again. Being listed, managed, online or running is never execution authorization. Directory and historical content remain untrusted data and are allowed in read-only transcript/viewer-Q&A contexts without granting writes.

No schema, retention policy, transcripts, history or takeover policy changes. Existing calls are not restarted. Backend combined-search repair works for older agents; the new structured tool schema and coordinator instructions require voice host Agent 0.30.105 and a naturally started new call. Web UI requires normal reload after safe publication; never force reload an active voice/streaming page.

Validation uses synthetic identities only: compound search, provider/host/project intersection, current running selection, stale rejection with duplicate receipts, scoped pagination, deleted-session exclusion, workspace isolation, empty-host discovery; UI expansion/filter/polling/error/race/visibility behavior. Production voice correctness is not inferred from these fixtures; no live task is dispatched to test this feature.
