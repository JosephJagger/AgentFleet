# Codex 原生能力差距复核（2026-10-02）

基线是主机实际托管的 **Codex 0.159.2**，面板代码 **AgentFleets 0.30.72 / e7cdd33**。这是整套原生协议与当前产品实现的比较，不是版本更新日志，也没有把账号专属能力当作所有账号都可用。未核实有无更高版本。

## 核查依据与边界

- 从该二进制重新生成默认及 `--experimental` JSON Schema；没有启动任务或消费重置卡。
- 对照本地主机 RPC 允许列表、操作执行器、任务与权限校验、控制端路由、前端入口与命令说明；并复查设置继承及会话/总控语音。
- 原生请求：默认 **104** 个；含实验 **167** 个。面板允许 **86** 个，其中默认 **69**、实验 **17**。缺少默认 **35**、实验 **46** 个请求。允许列表中的请求都存在于原生 Schema。
- 允许列表不等于完整实现：参数、分页、权限、结果展示、平台与账号验证还可能部分缺失。没有重新执行每个真实账号写操作，也没有逐一在 Windows/macOS 运行全部接口。
- 逐接口结果及参数名见 [机器可读清单](codex-native-coverage.json)。可复核：`node scripts/audit-codex-coverage.mjs /path/to/codex /tmp/coverage.json`。

## 本次语音问题的证据与修复

`PanelVoiceService.current()` 会返回用户最近的任务；旧 `poll()` / `report()` 只判断 `reported_call_id !== 当前通话 ID`。所以即使任务上次已播报，只要重新拨号，后台仍会把旧结果通过 `thread/realtime/appendText` 注入，并要求语音立即复述。

生产数据库只读复核发现已有任务的 `reported_call_id` 指向另一通话，证实出现过跨通话播报。未读取或导出任务正文、音频、SDP 或凭据。这个现象有面板代码与记录依据，不应归因于用户没说清楚或模型自行回忆。

修复规则：仅 `job.voice_id === 当前通话 ID` 且未确认播报的终态任务，才产生自动播报；确认回执也必须属于同一活跃通话。旧任务仍在状态卡和主动查询中可见，挂断不取消任务。新通话不会自动播报旧任务，即使旧任务恰好在新通话期间完成。

回归覆盖：同通话正常播报/去重、上通话已播报、上通话未播报、上通话任务延迟完成、新通话主动查历史任务、跨通话回执隔离。此修复在控制端，不改变音频原生传输或连接服务协议；不能据此声称所有网络断线原因均已修复。

## 服务端请求与有意限制

原生服务端请求共 11 类。常规审批、用户问题、MCP 常规表单、受限动态工具与时间请求有处理；敏感/不支持表单、外部令牌刷新、设备证明不能当成普通问答透传。未提供任意 RPC、任意环境变量或任意主机路径写入入口。

以上是代码和协议核查；需要真实账号或平台的能力，仍应以对应主机回执为准。
