# 安装与升级可靠性（0.30.84）

用户入口仍是主机页的「检查更新」「一键恢复连接」和「本机修复安装命令」，不需要 npm。无法在线修复的离线主机须在本机运行修复命令。

## 升级阶段与结果

后台先下载并校验版本、大小和 SHA-256，再等待任务和通话结束。激活前再次检查空闲状态，写入持久化升级事务，保存旧程序指针与运行配置，然后切换、重启和确认健康。新进程必须报告目标版本，连接完成同步且运行环境连续就绪 10 秒，才能确认成功；新进程启动确认超时为 90 秒。

安装脚本和自动更新共用事务。安装器持有本机独占锁；事务阻止另一次激活，版本清理遇到未完成事务会拒绝。事务记录阶段历史、更新目标、回退依据和确认时间。已确认回退后，迟到的成功消息不能覆盖结果。进程被中止后，下一次启动根据事务恢复。无法确认的操作仍保持待核验，不能因此重新执行用户任务。

面板分别显示实际运行版本、已安装版本、更新目标、升级阶段和回退版本。离线时是最后上报状态。安装器等待健康回执超时，只报「待确认」，不会报成功；回退指针恢复也不等于旧服务已联网，旧进程的健康回执单独确认。

macOS 使用 launchd 的异步状态确认，不将 exit 37 单独认定为最终失败。Windows 复用已有托管 Codex，并由独立 supervisor 完成受管更新；安装器失败后尝试恢复旧服务。Linux 同样沿用服务管理器和 supervisor。服务管理错误与运行时更新错误分别上报。

## 下载、重试和保留

POSIX 下载和 Windows 下载都有有限重试。已验证安装包可用于准备和激活阶段，缓存损坏时丢弃后重下；预检空间不足则停止。切换前校验预期目标，发布频道在下载过程中变化时重新准备。

短暂传输失败允许冷却后重试，激活失败同目标最多尝试三次。校验损坏、权限和协议不兼容不自动循环重装。手动修复仍可再次核查。不要删除失败记录来伪造更新成功。

健康恢复后沿用「附件和版本」的自动版本清理：保留当前版、回退版和仍被引用的文件，近期目录延后清理。首次安装没有可回退旧版本，面板上线确认仍是最终连接证据。系统临时目录中来源不明的残留不自动删除。

## 发布门禁

CI 包含 Linux、macOS 和 Windows 的升级生命周期测试，Windows PowerShell 5.1 解析和受管任务交接检查；全量测试、Linux 安装冒烟和不可变发布校验另行执行。测试替身覆盖事务与错误处理，不等价于所有实体机器的睡眠、关机、权限策略或网络环境。

可选 manifest.rollout: percentage (0–100 整数)、seed、platforms、notBefore。按机器身份稳定分组；不匹配的主机显示等待分批发布，0 暂停。缺省保持全量发布兼容。

**0.30.84 之前的客户端不支持 rollout 字段。** 首次引入此版本不能依赖该字段限制旧客户端；先完成 CI 与候选包验证，再更新公共 manifest。后续全部客户端支持后，按平台先小批、观察在线版本与回退率、再扩大；发现失败暂停新激活，保留旧的不可变下载链接。已开始的任务与激活不靠修改 manifest 强制中止。

发布后必须运行 `node packaging/verify-published-installers.mjs https://your-panel.example <版本>`。它核对公共 manifest、四平台校验文件和三个安装脚本的实际字节；反向代理的独立 alias 也必须随发布更新。仅重建容器不能保证公开安装入口同步，本次发现并纠正了网站仍指向 0.30.72/0.30.76 安装脚本的遗留路由。

## 0.30.85：Linux 准备阶段边界修正

0.30.84 的 Linux 脚本将 `--prepare-only` 退出误放进卸载分支，可能越过准备阶段执行运行时初始化和程序切换。0.30.85 将退出放在候选包完成校验和解压之后、任何当前版本链接、运行配置和服务操作之前。准备阶段只允许写下载缓存、安装锁与尚未激活的候选目录。

`python3 packaging/test-linux-prepare.py` 通过本地 HTTP 发布服务运行完整安装脚本，覆盖 portable/SEA、已有安装/无安装、重复准备和损坏校验。断言当前及回退链接、旧程序、Codex、运行配置、状态数据库和服务文件均不变，活跃测试进程持续运行，并禁止运行时、服务和 onboard 调用。root 分支在一次性容器中使用 `--isolated-root` 验证，测试不得在真实 root 安装目录中运行。旧脚本在同一测试中失败；两种权限的真实脚本检查均加入 CI。
