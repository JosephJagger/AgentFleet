# 工作树：多个智能体并行开发同一项目

同一主机上，Codex、Claude Code、Grok Build 等智能体可以在同一仓库的不同 Git 工作树里同时执行任务。

## 原理

面板的执行锁按**物理目录**互斥（`directory-turn-lock.ts`）：同一目录任何时刻只有一个任务在写，跨智能体也一样。工作树是独立目录，所以每个工作树有自己的锁，不同工作树之间不排队。锁本身没有改动。

每个工作树在面板中是一个**子项目**：主机上报项目时附带 `repoRoot`（主仓库根目录）、`branch`、`worktreeBase`、`worktreeRemoved`。`repoRoot` 存在且不等于自身目录即为工作树。同一工作树可被多个智能体各自登记为项目（「让其他智能体加入」），它们共用该目录的锁。

## 功能

- **新建会话时**：「配置本地环境 → 新建工作树 / 分支 / 环境」，与 Codex 桌面版一致。会从所选本地分支创建 `af/<名称>` 分支和工作树，登记为子项目，并在其中创建会话。
- **会话工具栏「工作树」**（所有智能体）：
  - 主目录当前分支和未提交文件数；
  - 新建工作树（选择智能体、分支、名称、环境）；
  - 每个工作树显示：分支、领先/落后、未提交文件、最近提交、已加入的智能体和会话、与其他工作树改动重叠的文件；
  - 查看差异、合并到主目录当前分支、让其他智能体加入、删除；
  - 「其他工作树」：Codex 桌面版或手动创建的工作树，可接入面板。
- **位置**：`<仓库父目录>/.<仓库名>.worktrees/<名称>`。
- **环境**：仓库中存在 `.agentfleet/worktree-setup.sh` 时可选择运行；在新工作树目录中以 `sh` 执行，超时 15 分钟。环境变量 `AGENTFLEET_LANE`（工作树序号，可用于错开端口）、`AGENTFLEET_WORKTREE_SOURCE`、`AGENTFLEET_WORKTREE_BRANCH`。脚本失败时工作树保留，并提示失败。

## 安全约束

- 新建、合并、删除走持久化的主机操作（`worktree.create|merge|remove`），可重试且有审计；读取（概览、差异）走请求-应答帧 `worktree.read` / `worktree.result`。
- **合并**：控制面先确认工作树目录和主目录都没有任务在运行（同一把目录锁），主机再核对一次；工作树有未提交改动、主目录有未提交改动、没有新提交时都会拒绝。先用 `git merge-tree --write-tree` 预检，有冲突直接拒绝并列出冲突文件，不会碰主目录；合并失败会执行 `merge --abort`。
- **删除**：工作树里有任务在运行时拒绝；有未提交改动时需要确认放弃。分支用 `git branch -d` 删除，未合并则保留（确认放弃时用 `-D`）。项目标记为已移除后从列表中隐藏，会话历史保留。
- 只能从主仓库项目新建工作树，工作树不能再作为来源。名称、分支、路径都在控制面和主机两端校验。

## Codex 沙箱

Codex 的 `workspace-write` 沙箱有意把 Git 元数据设为只读：实测在主目录和工作树里执行 `git commit` 都会被拦，额外放开主仓库 `.git` 也无效。因此在工作树里提交与在主目录一样，需要审批放行；沙箱边界没有改动。Claude Code 和 Grok 不受此限制。
