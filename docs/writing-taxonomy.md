# 输入辅助词库分类规范

词库采用两个独立维度：**建议类型**（术语补全、表达优化）和**知识分类**（领域、子类）。人工编写、开源导入、自动学习、模型生成属于来源，不能当成知识分类。

## 领域与子类

领域不按产品品牌划分。AI 基础技术归人工智能；工具接入、任务执行和多智能体协作归智能体；数据统计方法独立于办公流程；金融应用引用统计概念而不重复建词。

## 数据约定

- `writing-taxonomy.json` 是领域和子类的唯一登记表。新增分类须先在此登记，再新增词条。
- `writing-glossary.json` 每个专业概念有稳定 `id`、主领域 `domain`、子类 `category`、中英文名称 `terms`、说明 `definitions`、别名 `aliases` 和来源、许可。已发布 ID 不随名称调整而改变。
- 跨领域概念使用 `relatedDomains` 关联，保留一个主分类。例如客户获取成本属于数据指标，关联电商、运营和营销；幸存者偏差属于认知偏差，关联金融。
- `writing-corpus.json` 保存表达意图、目标和双语例句。引用已有概念时使用 `conceptId`。多个不同说法归入同一个意图；不用重复意图争抢同一句话。
- 英文缩写只作为对应概念的别名。歧义缩写不能直接推断任务意图；需依上下文排序。专业名词的语言不决定说明文字的语言，说明跟随界面语言。
- 原有开发基础词和开源软件单词表仍走现有补全路径，不计入本表专业概念数量。软件通用词汇只提供词形补全，未经审核不得自动赋予精细专业含义。
- 自动学习内容仍保留个人或项目范围，不直接写入公共专业词库。学习结果目前未自动分配上述细分类；不能仅凭出现频次强行归类，后续需用置信度和未分类状态扩展。

## 发布与验证

运行 `node apps/control-plane/scripts/export-writing-terms.mjs` 生成前端专业词条和表达示例。生成器检查稳定 ID 唯一性、分类归属、引用、来源许可以及中英文说明覆盖；跨语言词条共享概念编号。术语命中与 NLP 表达意图分别测试，语义检索还需跑留出集检查误匹配。

分类目前用于语料组织、校验和 NLP 元数据，不新增要求用户选择分类的步骤，也不代表输入辅助已能理解任意表达。补全列表保持现有“术语 / 表达优化”标签。

## 常用工作流与科技新闻扩充

本轮覆盖产品需求、交互设计、测试排错、部署运维、文件自动化、数据库与集成、移动端、安全权限、研究教学九类工作，共新增 107 个专业概念、27 个表达意图和 108 条中英文示例。已有概念直接复用。分类以知识含义为主，不以某一职业或产品品牌重复建表。

科技新闻新增 26 个半导体、算力、通信、航天与能源概念。69 个已有 AI 和 Agent 概念通过 `relatedDomains: ["technology"]` 关联，仍保留原有 ID、定义和主分类。科技新闻分类不表示新增了一套重复词典，也不自动获取实时新闻。

原开源软件词表已有的缩写，在具备完整专业定义后由专业词条接管候选显示，例如 GPU 只显示有说明的图形处理器概念，避免同时出现无说明的重复缩写。

专业词库现共 499 个概念、93 个表达意图，分类登记覆盖 18 个领域。科技领域本次只补术语，不为新闻编造事实或新增新闻分析结论。

语义评测使用独立样例，运行 `WRITING_MODEL_PATH=/path/to/model node apps/control-plane/scripts/eval-writing.mjs --workflow`。固定阈值维持不变；含糊说法仍可不出建议。评测记录见 [工作流评测](writing-workflow-evaluation.json)。

本轮验证：前端相关测试 107 项、后端词库与 NLP 测试 31 项通过；65 条语义留出样例中 12 条命中、27 条保守放弃、26 条无关输入拒绝、0 条错误建议。专业术语补全与固定例句不依赖语义模型命中；未知说法的召回仍有明显提升空间。
