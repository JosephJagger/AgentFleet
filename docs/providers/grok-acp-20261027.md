# Grok ACP alignment — 2026-10-27

This supersedes the current-behavior sections of [the 0.30.135 audit](grok-native-135.md), which remains a historical release record. This work uses the ACP process, not a TUI wrapper. No release or production migration is part of this change.

## Evidence and corrections

- Installed native binary: **Grok 1.0.70 (`f50904eaee6c`, stable)**. Earlier repository evidence used 1.0.62. Agent 0.30.135 is an earlier integration release, not the Grok version; the task branch started from Agent 0.30.153.
- Native source contracts reviewed at [`2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`](https://github.com/xai-org/grok-build/tree/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8). Public source and installed releases are separate evidence; synthetic tests do not prove every extension works with every installed build.
- ACP exposes `session/set_mode` even though `configOptions` lists only `model` and `reasoning_effort`. `--permission-mode plan` is not the way to enter plan mode on agent stdio/serve. Plan mode gates native editing tools; it is not a filesystem sandbox and does not guarantee that shell commands or subagents cannot write.
- The installed handshake advertises `grok-4.7-build-fast`. A separate fast toggle is not needed to select that advertised model. Parameterized model IDs are accepted only if the native catalog/config options advertise them; accepting their syntax does not invent account entitlement.
- Session info, files, terminal and authentication have native extension surfaces. Calling them “TUI-only” would be incorrect. Exposing an extension safely in this application still requires lifecycle and account/workspace scope handling.
- Permission notification has no effective-policy acknowledgement. A successful send and subsequent RPC establish that the connection remains responsive, not that native policy accepted every requested permission.

## Implemented behavior

| Area | Result |
| --- | --- |
| Plan mode | Probe the actual handler; switch with `session/set_mode` before the next prompt. An unavailable/rejected setting fails before sending the task. Require the native RPC acknowledgement before prompting; mode notifications can arrive later or be omitted for an unchanged mode. Explicit `default` is retained and clears plan mode. |
| Plan execution consent | Handle `_x.ai/exit_plan_mode`. Show the complete supplied plan, then collect explicit approval, revision feedback, keep-planning or abandon. Tool auto/always approval never answers this request. Native `approved`, `cancelled` and `abandoned` responses are distinct. Approving or abandoning stores the next requested mode as explicit `default` and reports the completed turn as default. Keeping the plan or sending revision text leaves the saved plan mode unchanged. A settings snapshot read before that session update is not sent on the next turn; the server applies its saved row until a newer read arrives. A save response that is not newer than the latest known revision is ignored, and a save is fresh only for the session sequence at which that request was sent. |
| Native interviews | Handle `_x.ai/ask_user_question` for single-choice, multi-select and free-text questions, using original question text as answer keys and native `Other`/annotation format for typed answers. A multi-select answer is the chosen labels, plus at most one free-text note as `Other`. An omitted or JSON `null` multi-select flag is single-select. Option previews still cancel the question. “Chat about this” and “skip interview” are not exposed. |
| Permission requests | Owned Grok processes use `--no-leader`. On the verified 1.0.70 build, auto and explicit ask mode stay in the same process and send `_x.ai/yolo_mode_changed` before the prompt, including resumed sessions. Entering or leaving always-approve reconnects, including a return from always-approve to an unset choice, because `--always-approve` is a process launch flag. An unset choice does not send an ask-mode notification and is not coerced into explicit default. |
| Honest state display | Show the next requested settings separately from the previous turn's native mode and timestamp. Permission state is recorded as **requested**, never effective. Unset preferences display “use native settings”; unknown native versions cannot request automatic review or force a return to ask-mode without a verified synchronization contract. |
| Model/effort | Require exact native confirmation before prompting; do not accept an empty/no-op configuration reply. Preserve native catalog restrictions, including parameterized IDs. |
| Interjected images | Preserve verified 1.0.62 support and add 1.0.70 when image capability is advertised. Unverified builds fail instead of silently dropping the image. |
| Native visibility | Add session/context info, workflow listing and skill-source configuration reads. A workflow row whose name matches `^[a-z0-9-]{1,64}$` can fill the composer with `/workflow <name>` without sending. A successful `session.fork` requests a catalog scan so the new session can appear; the fork receipt is not registered as a panel session, and a scan failure does not fail the fork. Existing native task, subagent, memory, plugin, hook and Git reads remain. |
| Extension controls | Add listed-skill enable/disable, listed-MCP-server enable/disable and listed-MCP-tool enable/disable. Native field casing is preserved; missing/foreign targets fail before mutation. These native settings can affect other sessions and the confirmation states that scope. |
| MCP forms | Support optional primitive fields with an explicit skip choice; omission is distinct from `false` or `0`. Unsupported forms respond with native cancellation rather than an unknown-method error. |
| Project files | Add native directory listing (50 entries/page) and bounded file reads (4000 bytes/page), with an explicit offset. Resolve paths within the managed session workspace and reject paths escaping through symlinks. |
| Git index | Add explicit single-file stage/unstage. No wildcards, directory-wide operations or implicit `git add` during commit. Unstage preserves working files. |
| Export | Export the currently displayed, bounded, sanitized native-operation result with its observation time. This is not full session export. |
| Server checks | Preference saves and direct turn payloads both check plan/permission capability. A stale or manually constructed request cannot bypass those checks. |

Existing command leases, active-turn preconditions, native identity checks, action hashes, explicit mutation confirmations, background/subagent-idle checks and unknown-outcome handling remain in place. Startup rules/profile/system-prompt metadata remains creation-only; resuming a session never overwrites its instructions.

## Remaining boundaries

### Native protocol/runtime constraints

- The reviewed scheduler ACP handler only exposes deletion and notifications, not a complete list/create contract. `/loop` can be an ordinary explicit prompt, but cannot be represented as a reliable structured scheduler CRUD API.
- No effective permission-state acknowledgement is available for the reviewed notification. Policy, remote restrictions and native environment can clamp the request. The panel cannot honestly report enforcement from a successful notification alone.
- Plan mode is not an OS sandbox. Cross-platform confinement cannot be established by relabeling tool approval or adding an unverified flag.
- Native daemon JavaScript workflow pause is not a general manual pause API; budget-triggered suspension/resumption must not be presented as arbitrary pause/resume.
- Pager/TUI rendering and keybindings are not supplied by ACP. Theme, density, vim, full-screen, leader dashboard layout, pager queue, external editor and native status bar would need separate panel implementations or a separate terminal transport.
- Native account/model entitlement, OAuth grants and platform-specific sandbox support remain external prerequisites. The adapter cannot manufacture them.

### Available natively, but not implemented in this patch

These are engineering gaps, **not claims of impossibility**:

- Per-session `--allow`, `--deny`, `--tools`, `--disallowed-tools`, `--sandbox` and arbitrary startup flag editing. Handshake/tool-definition counts did not establish filter enforcement, so no “effective restriction” UI was added. Native `config.toml`/CLI remains the supported setup path.
- Workflow run/start/stop/resume/budgets and daemon ownership/recovery, scheduler creation through an alternative documented service, and subagent sessions attached as independent panel sessions.
- MCP server creation/removal, URL/OAuth/secret authorization, complex forms, and injected `mcpServers`. New sessions still send `mcpServers: []`; existing native-configured servers remain usable.
- Hook creation/trust/untrust and pinned-hook changes; arbitrary plugin sources and marketplace editors; skill source editing.
- Git discard/amend/push/sync, worktree deletion/gc, native file writes/index notifications and a persistent native terminal lifecycle. Existing panel SSH is a separate transport.
- Native login/logout/privacy/ZDR, cross-host account deduplication, usage management, full-session export, stable replay IDs and automatic registration of a fork receipt as a panel session. A successful fork only requests a catalog scan.
- Dedicated media-generation/persona/memory-diagnostic interfaces and Codex-specific attachment/schema/plugin inputs for Grok. Ordinary native prompts remain the entry point where applicable.

### Explicit limits of the new implementation

- Plan approval requires complete non-empty plan text up to **64,000 characters**; empty/oversized plans are cancelled with explanatory feedback instead of approving a truncated preview. Native TUI can handle an empty plan differently.
- A reverse approval emitted during `session/load` has no active managed turn and is cancelled. It is not resurrected as a fresh execution authorization. Ask Grok to submit the plan again in the next explicitly started turn. Pending approvals are invalidated on cancellation/disconnect; browser reload during the same live turn uses the existing durable approval flow.
- Native interview option previews, partial interviews, “chat about this” and “skip interview” actions are not exposed. Multi-select is supported: one or more option labels, or a single free-text note recorded as `Other`. An omitted or JSON `null` multi-select flag is single-select. Conflicting multi-select flags, secrets, duplicate labels and option previews cancel or reject the question. No answers are fabricated. Native interviews and MCP forms have at most eight questions and the existing ten-minute panel approval expiry.
- Permission synchronization is enabled for the verified **1.0.70** contract only. Other versions require validation before enabling auto mode or explicitly resetting to ask-mode; this is a version gate, not a statement that newer Grok lacks the feature.
- Bracketed model syntax must be advertised by the host. No arbitrary custom model string/fast override is sent.
- File reads remain bounded pages. Binary content, UTF-8 boundary handling and native offsets retain native semantics; display/export uses the existing 100-row/24,000-character sanitizer. This is not an unrestricted file editor or full archive export.
- Memory deletion still requires the existing complete UTF-8 preview of at most 4000 bytes and a fresh content hash. Large/binary notes remain native-client work.
- Native task completion is determined by the foreground `session/prompt` response; workflow/subagent/task notices do not substitute for it.

## Validation

See the final validation results below. Tests use synthetic ACP peers and isolated temporary workspaces. Authenticated probes use a private temporary `GROK_HOME` and never load real user sessions. They do not install plugins, alter real Git state, delete user memory or publish anything.

The real 1.0.70 adapter plan probe observed an empty temporary workspace before explicit plan approval, a native transition to default mode after approval, and a separate file-write permission request. The probe declined that write: the turn was interrupted and the workspace stayed unchanged. This verifies that plan consent does not replace later tool approval. A separate native image interjection probe queued a red PNG during a temporary turn and received a correct red-image answer.
