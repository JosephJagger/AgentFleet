# 智能体版本与可选托管更新

入口：**主机 → 附件和版本 → 智能体版本管理**。配套新版面板和 Agent 0.30.109 起的连接服务须同时具备 `provider.runtime` 能力。旧连接服务仅展示已有版本，操作按钮禁用；发布面板本身不会更新主机代码。

## 使用方式

- **检查智能体版本**：汇总 Codex、Claude Code、Cursor、Qwen Code、Kimi Code、CodeBuddy Code、Grok Build 的实际版本及来源。检查不会安装、切换版本、登录或发送任务。
- Claude **沿用宿主机安装**（默认）：保持原安装器及更新设置；不会替用户执行 npm、brew、winget 或改写原生设置。
- Claude **托管 · 固定版本**：首次选择下载官方 stable 版本至连接服务私有目录，验证后切换。已托管时选择此项仅固定当前版本。
- Claude **托管 · 自动更新稳定版**：显式选择才启用；约每六小时检查一次，后台调度最多另有五分钟延迟。先校验再切换，不自动降级到较旧 stable。
- **回退并固定版本**：切回之前成功启用的托管版本，暂停后续自动更新。首次托管还没有旧托管版本，可切回仍然存在的宿主机安装。

作用范围为**这台主机上 AgentFleets 启动的 Claude 进程**。原生终端仍按自己的安装运行；不改写 PATH、用户账号、CLI 配置、历史或项目文件。Codex 的验证器、晋升通道和更新器保持原有机制。其他五个 ACP 智能体此轮提供盘点和已有协议证据，没有开放未验证的独立分发/回退适配器；其升级仍由原安装方式负责。

## 验证分层

1. 官方 `stable` 给出候选版本；固定官方 HTTPS 域名，拒绝重定向、路径、任意版本、URL、包名和 shell 命令输入。
2. 官方 `manifest.json` 必须带有效的官方 OpenPGP 分离签名（`manifest.json.sig`，2.1.89 起提供）：签名密钥内置并固定为指纹 `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE`（与[官方文档](https://code.claude.com/docs/en/setup)一致），不从下载源获取密钥；缺签名、签名不符或签名者不是该密钥都拒绝。清单还须精确对应版本和平台，提供受限大小、SHA-256，以及 `sdkCompat.harnessSchema=1` / `testedWrapperVersions` 中的项目 SDK 版本。缺字段、不匹配或源不可达不晋升。
3. 下载到独立临时文件，核对字节数和摘要，原子移动到版本目录。实际 `--version` 必须匹配。
4. 使用项目固定的 `@anthropic-ai/claude-agent-sdk` 执行 `supportedModels()` 控制握手，临时空目录、禁用项目设置/工具/MCP、不持久化会话、不发送用户 prompt。此检查**不是认证、写入、审批、取消、历史恢复或真实任务完成测试**，UI 只写「协议检查通过」。
5. ACP 仅在同一个实际版本已有成功协议协商时显示协议检查证据。未安装、无证据或版本变化不能显示已验证。

SDK 升级时必须同步版本常量（测试会检查），旧托管文件在重新验证前不可冒充新的 SDK 组合。可用状态不构成执行授权，原任务授权链不变。

## 安全切换和失败

- 下载/检查不重启服务；真正切换复用 StateStore 的原子更新准入与 maintenance drain。活动/未知命令、项目预留、审批、会话语音、总控语音或其他维护会阻止切换。
- 自动检查在忙时推迟。手动申请遇忙保留已验证下载并报告待空闲，此次不会擅自改策略；用户空闲后重新应用。已启用自动模式的等待项继续在后台检查。
- 激活只释放空闲 Claude writer 并刷新 Claude 路径，不重启 Codex、连接服务或控制平面。并发旧目录读取不能覆盖新路径。
- 激活失败恢复旧指针；若此前为自动模式，转为固定版本。协议/下载失败保留实际版本并报告阻塞；相同失败不会被后台反复执行，手动检查/应用可重新核验。
- **只保留当前与上一托管版本。** 每次操作结束和连接服务启动后的首次自动检查都会清理 `provider-runtimes/claude` 中其他版本目录（命名为 `版本-SHA256` 的才会删，其他文件不碰）；等待主机空闲的已验证候选版本会保留以免重复下载；超过一小时的残留 `.partial` 文件会移除。正在使用而无法删除的文件（Windows）留到下次再试。
- **首次启用托管不会降级。** 若宿主机已安装的 Claude 比官方 `stable` 更新（`stable` 通常落后约一周），选择"托管"会被拒绝并说明原因，继续使用宿主机版本；不会进入阻塞状态。已托管后的自动更新仍只前进、不降级。
- **自动更新会自愈。** 网络类故障（官方站不可达、超时）只记录提示、不进入阻塞，约 30 分钟后重试；清单未确认 SDK、签名或摘要等验证类失败标为阻塞，约 6 小时后自动重新评估（只取清单，不会重复下载）。同一个稳定版本验证失败累计 3 次后不再自动尝试，等待新的稳定版本、重启服务或手动重试。回退、固定版本或启用失败仍会停止自动更新，需用户重新选择。
- 托管进程的 `DISABLE_AUTOUPDATER=1` 仅设置在子进程环境，不修改宿主机原生自动更新设置。
- 策略存于本机 StateStore，默认 host；修订号用于保存冲突，维护操作沿用登录、CSRF、工作区校验、幂等键和审计。中断的写操作标为未确认，不自动重放。
- 控制平面 schema 62 仅扩展维护操作类型，迁移保留旧操作、索引及外键。发布依旧必须等待通话自然结束并走守护发布器。

## 实际验证范围

Linux x64 隔离验证：真实官方 Claude 2.1.292 下载/摘要/版本/SDK 0.3.285 握手成功；宿主机 2.1.296 的只读握手成功。使用临时 StateStore 和临时目录，没有切换生产主机、重启服务或向真实会话发送任务。

单元/集成验证覆盖原子准入、通话阻止切换、失败回退、固定策略、不变版本不重启、冲突、幂等、中断不重放、旧数据库迁移、UI 选择与旧服务能力限制。Windows/macOS、其他架构、真实账号执行和长时间自动升级仍需专机实测；不能从 Linux 握手结果推断已全部认证。

## SDK 兼容性预警

官方清单的 `testedWrapperVersions` 是滚动列表；项目固定的 SDK 一旦掉出该列表，自动更新会因 `PROVIDER_SDK_UNREVIEWED` 停止。运行 `npm run check:claude-sdk`（不属于 CI 必过项，可放在定时任务）会比对固定 SDK 与当前 `stable` 清单、列出 npm 最新版：不在列表中退出码为 1，位于最旧的 8 项以内给出警告。收到警告后按"SDK 升级必须同步版本常量"的要求升级并发布新的 Agent 版本。

## 新版本发现与确认更新

原则：**发现是自动的，更新必须由你确认**。

- **自动发现（只读）**：连接服务约每六小时读取一次各智能体的官方最新版本（Claude Code 的 `stable`；Qwen Code、Kimi Code、CodeBuddy Code、Grok Build 的 npm `latest` 标签），结果只写入「智能体版本管理」的提示，不下载、不安装、不改动任何设置。某个来源不可达时保留上次的值，其他来源照常更新，不影响运行中的智能体。Cursor 没有公开的版本查询接口，暂不提示。Kimi 的新大版本（Python → Node.js 发行版）按迁移处理，不当作普通更新提示。
- **Codex**：官方稳定版经验证器验证、晋升后，主机**不再自动切换**。主机只显示「已验证，等待你确认更新」，你点击「确认更新到 x.y.z」后才下载、等待空闲、本机验证并切换，失败回退机制不变。确认只对当前提示的那一个版本有效，版本变化后需重新确认；切换成功或失败后确认即失效。回退目标和损坏运行时的修复不需要确认。若需恢复旧的全自动行为，可在主机服务环境中设置 `AGENTFLEET_RUNTIME_UPGRADE=auto`。
- **Claude Code**：托管版本（固定/自动）有新稳定版时显示「更新到 x.y.z」，点击后走原有的验证流程（官方签名、摘要、SDK 与协议检查，空闲时切换，可回退），并保持原来的模式。「自动更新稳定版」是你主动选择的模式，不再重复询问。宿主机安装只提示新版本，由其自带的更新方式处理。
- **其他智能体（Grok 除外，见下方第一阶段）**：只提示「有新版本，请用原安装方式更新」。这些 CLI 没有可验证的官方分发清单（无签名/校验和），面板不会替它们下载或执行安装命令。

网络与权限：Codex 确认和 Claude 更新沿用原有的登录、CSRF、工作区校验、幂等键与审计；请求格式只允许固定字段（版本号只接受 `x.y.z`），不接受路径、URL 或命令。

## 谁可以控制版本

Codex 运行时和连接服务（Agent）由本面板分发，什么时候变更是运营者的决定，因此以下操作**只有平台管理员**（部署配置 `ADMIN_EMAIL` 对应的账号）可以执行，由控制面服务端强制校验，普通成员即使绕过界面直接调用接口也会得到 `403 ADMIN_REQUIRED`，且不会产生任何操作记录：

- 确认 Codex 托管运行时升级（`provider.runtime` 的 `confirm`）
- 检查并更新连接服务（`agent.update`）

非管理员在界面上仍能看到「等待确认」的状态，但按钮被隐藏或禁用，并提示需要平台管理员。

Claude Code 的更新策略、更新到新稳定版、回退，以及其他智能体的版本提示，属于主机所有者自己的决定，保持对工作区成员开放。Codex 渠道的暂停/恢复/回退原本就只对平台管理员开放。

### Codex 状态对非管理员不可见

非管理员只能看到每台主机上 Codex 的**版本号**。Codex 的升级阶段（等待确认、准备中、切换中、失败/回退）、托管目标版本、验证状态与协议摘要，由控制面在返回给浏览器之前就移除（`/api/dashboard`、`/api/machines`、`/api/machines/:id`），而不是仅靠界面隐藏。界面上对应的「Codex 兼容档案」、更新中心里的升级进度、版本管理里的来源与兼容标签和确认按钮，也只对平台管理员显示。

不在此列：主机是否可用于任务的整体健康状态（例如只读、需要处理的告警），这些影响所有成员的日常使用，仍然显示。


## 多智能体托管第一阶段（连接服务 0.30.152）

管理 → 托管升级采用程序导航、目标版本、工作区主机列表的统一布局。Codex 保留现有验证与晋升渠道；Claude Code、Grok Build 新增独立渠道。连接服务单独列出，复用已有手动更新与健康回执。手机使用两列程序选择，主机操作另起一行。Qwen、Kimi、Cursor、CodeBuddy 仅列入后续接入范围。

Claude/Grok 每六小时检查官方元数据，也可手动检查；**发现新版本不会自动发布目标或更新主机**。管理员确认精确候选摘要与渠道修订号后发布全站目标。主机上的手动确认绑定该目标摘要与操作修订号；工作区成员可管理自己的主机，旧连接服务必须先升级。Claude 原先主动开启的自动更新策略保持原状，选择平台目标后固定该版本。

- Claude：中央校验固定官方密钥的签名清单；主机再次核验官方签名、大小、SHA-256、SDK 兼容性与启动协议。
- Grok：固定官方 npm 版本与平台包 SHA-512，仅从已验证包中读取指定常规二进制文件（包括 Brotli 包装），不运行 npm 安装脚本。主机核对实际版本并完成 ACP 初始化后启用。
- 独立目录保留当前和上一个成功版本；任务与通话等现有运行时维护闸门允许后才切换。失败恢复原选择。Grok 可明确回退到保留版本；Claude 沿用主机托管设置中的回退功能。全站“回退目标”与主机“回退版本”分开，前者不立即降级主机。
- 下载、校验、等待空闲、启用、完成、取消、失败、待核验均由持久状态上报。接受维护命令不代表更新完成；完成后仍需实际运行版本与目标一致。等待空闲可取消；重启保留等待意图，但中断的执行标为待核验。确认超过 24 小时或目标改变须重新确认。

协议通过不等于完整任务兼容。第一阶段在 Linux x64 实测 Grok 1.0.70 的包摘要、实际版本和 ACP 初始化；其他平台启用时由主机执行同样的校验。中央候选列表不是跨平台真实任务验证报告。


平台匹配使用主机 API 的 `platform` 与 `architecture`，系统展示文本（例如 `linux 26.04`）不参与安装包键匹配；CLI 的版本描述先提取版本号再比较。运行连接服务 0.30.152 及以上的主机在管理列表、主机详情和更新中心共用托管操作，不再显示旧 Claude 更新方式表单。Claude 的固定版本、回退和切回宿主机安装放在行内“版本选项”，沿用策略修订号和明确确认；尚未升级连接服务的主机保留旧入口。
