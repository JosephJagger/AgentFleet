# Read-only conversation history for panel voice

Agent 0.30.89 adds `history` to `agentfleets_panel`. It queries a precise authorized
session independently of coordinator jobs and progress caches. Idle sessions and
conversations originally started by typing or in a native client are supported.
Historical text is data, never a command or authorization to dispatch work.

## Interfaces and isolation

- Authenticated `GET /api/sessions/:id/conversation-history` accepts optional
  `machineId`, `projectId`, `mode=latest|page`, `source=auto|native|synced`, `cursor`.
- Voice action `history` takes the same fields, with required `sessionId`.
  Resolve ambiguous targets using search first. Supplied host/project must match.
- Default `auto` tries the connected host, then explicitly falls back to durable
  synchronized conversation events if the host is offline, old or unavailable.
  `native` never silently falls back. Subsequent cursors pin the source.
- Authorization is the existing workspace/session policy; voice additionally
  requires ownership of the active call. Content sharing must be enabled. Known
  deleted/expired content is not restored through native reads.
- Read requests use a separate, correlated, bounded Agent relay RPC. They create
  no command, job, writer, native turn, takeover or resume. Connection generation,
  native process epoch, project, thread and content epoch are checked. Late replies
  from a previous connection are rejected. At most two reads per host are pending;
  host timeout is 20 seconds.

The actual Codex protocol uses the **existing app-server stdio connection**:
`thread/read` with `includeTurns:false`, then `thread/turns/list` with
`itemsView:full`, descending order for paginated stores. Legacy stores use
`thread/read` with `includeTurns:true`. No assumed HTTP/SSE endpoint is involved.
See [OpenAI app-server documentation](https://learn.chatgpt.com/docs/app-server).
The request shape was also checked against schemas generated by Codex 0.160.1.
The Agent facade routes reads through its existing catalog connection, not a
new session writer.

## Results and pagination

Responses identify host/project/session, `source`, `authoritative`, `availability`,
`nativeError`, `unavailableReasons`, `items`, `latestRound`, `nextCursor`, `hasMore`
and `truncated`. Each dialogue message retains ID, turn ID, user/assistant role,
phase, time and time source. Missing native timestamps are null or explicitly
identified turn timestamps; cloud records use synchronized event timestamps.

Native pages contain one persisted turn, up to 20 dialogue messages; cloud pages
contain up to 20 synchronized dialogue items. Latest mode starts with the last
turn; follow `nextCursor` for the rest and earlier turns. Items within each page
are chronological. Cloud pages advance backward by persisted event sequence;
late imports can differ from native chronology, so cloud history is always marked
partial/non-authoritative. Native turns may be split over pages.

Long messages are split into 20,000-character chunks with `textOffset` and
`textLength`, retaining the same item/turn IDs. Follow the cursor and concatenate
chunks by offset for the complete available message. A page has at most about
100,000 text characters. `latestRound.complete` describes only the returned
user/final pair, not completeness of the entire session. If either lies on another
page, follow the continuation before claiming a complete answer. Final replies
are identified by `final_answer`, or the last non-commentary assistant message
of a completed turn on older protocols.

Only user and assistant dialogue is exposed, including commentary. Tool logs,
internal reasoning, attachment bytes and audio are not included; non-text user
content has type placeholders. This is not a raw export of every native item.
`status`/`progress` remain the interfaces for running work.

Empty native history, missing cloud history, offline hosts, unsupported interfaces,
permission denial, deleted sessions/content, expired content, changed identities
and timeouts have distinct states/error codes. An empty progress array is never
used as evidence of missing history. Signed cursors are bound to user, session,
content epoch and execution segment. Server restart invalidates cursors; restart
reading that session instead of substituting another session.

## Delivery

Publish the prepared panel with `packaging/deploy-control-plane.py`; active calls
must finish naturally. Do not restart a voice host or replay old tasks for this
feature. Native reads require target Agent 0.30.89; older targets can supply only
already synchronized history. The voice coordinator host also needs 0.30.89 and
a new call to load the new tool schema/instructions. Existing calls are preserved
and are not force-refreshed. No new database migration is needed for history;
the preceding voice-safe publication migration remains required.

## Voice during catalog resynchronization

An existing panel call keeps its verified host/process/generation binding for
heartbeat, stop and tool replies while the same socket resynchronizes its catalog.
New calls, task admission and native history requests still require completed
reconciliation. The retained verification is never reused after a transport or
native process change. Older Agents can briefly defer controls until reconciliation
completes; their existing 120-second voice watchdog still applies to prolonged
loss of contact. This does not promise audio survival through a real host restart.
