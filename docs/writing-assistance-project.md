# 跨领域输入辅助与对话经验库

状态：首个可运行闭环已实现，schema 31。以下区分当前能力与后续项目目标；不能将原型视为已覆盖任意表达。

## 产品结构与取舍

三个模块共用来源和权限约束：

| 模块 | 当前实现 | 后续工作 |
| --- | --- | --- |
| 术语匹配 | 本地前缀、拼写容错、双语概念、自动积累的个人/项目词条 | 更丰富的别名、定义、多义消歧与领域筛选 |
| 表达建议 | 分词规则 + 本地多语言向量召回；专业任务目标与原描述一起保留 | 对象/目标/约束槽位、澄清选项、可验证的受控改写 |
| 问答记录与学习 | 原始角色分离、按原生轮次关联、自动提取入库、来源引用与清理 | 历史案例检索、纠正链、采用后编辑和发送反馈 |

不以“每领域必须几百条”作为验收标准。先把编程、Agent、办公做深，工程、游戏、视频各覆盖少量常见场景，按漏召回和误建议扩充。语义检索在项目早期验证；不能等扩充到大量词条以后才发现模型不适合中文。

未配置外部 AI 时：即时词库、自动提取和自建后端 NLP 可用。外部 AI 仍为独立配置与显式操作，不参与每次输入停顿。

## 当前语料

`apps/control-plane/src/writing-corpus.json` 是版本化的团队原创 CC0-1.0 语料：29 个双语概念/场景、147 个中英文示例，覆盖六领域。它们不是 29 个已完全解决的自然语言理解问题。

| 领域 | 当前例子 |
| --- | --- |
| 编程 | 会话失效、点击无响应、移动布局、列表性能、保存失败、防抖、重复提交、接口超时 |
| Agent | 操作审批、中断恢复、上下文保留、工具调用、并行任务 |
| 办公 | 数据核对、表格合并、去重、定期报表、文件整理、邮件工作流 |
| 游戏 | 穿墙碰撞、掉帧、存档恢复 |
| 视频 | 音画同步、字幕、色彩匹配 |
| 工程 | 装配公差、网格收敛、图纸版本 |

稳定 ID、领域、中英文名称、任务目标、示例、来源和许可都在数据文件中。单个概念的中英文名称不重复计算概念数。CSpell 的 3,943 条软件拼写词汇另计，不冒充中文语义覆盖。

从同一来源导出浏览器词条：

```sh
node apps/control-plane/scripts/export-writing-terms.mjs
```

数据校验测试检查 ID 唯一、六领域、双语示例的预期匹配和建议长度。当前尚无在线语料编辑/审核发布台；修改数据经代码评审和版本提交发布。

## NLP 与中文边界

1. 浏览器即时补全保持原有速度。
2. 停顿 600ms 后，当前草稿发往本站后端，中文和英文均支持。
3. ICU 分词、同义组合与明确示例先匹配；多意图冲突拒绝输出。
4. 没有词面命中时，本地 MiniLM 多语言模型进行向量召回。最高相似度至少 0.74，领先第二名至少 0.08 才输出；相似度不是正确概率。
5. 使用语料中受控的专业任务目标，同时完整保留原句及替换偏移，不从相似度推断根因、技术方案或补造参数。

这仍有明显限制：否定识别主要是规则；多问题、复杂约束、领域多义和隐含指代不能保证理解；当前模板是专业目标 + 原始描述，尚不是自由改写器。向量仅索引公共原创示例，不索引私人聊天、自动积累词条或工具输出。未命中时不强行建议。

本地模型固定为 `Xenova/paraphrase-multilingual-MiniLM-L12-v2` 的 revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`，q8，384 维。Apache-2.0。模型在构建时下载，运行时禁用远程模型访问，不需要 API Key。CPU 工作线程启动后预热；线程内序列推理，最多四个待处理请求，1.5 秒超时降级；主线程继续处理会话事件。前端总超时 2.5 秒。

模型暖机或不可用时自动保留词面 NLP；接口附带 `semantic` 状态便于验证。草稿只短暂驻留内存，不写入数据库、文件或请求正文日志。

参考：[模型说明](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)、[本地模型配置](https://huggingface.co/docs/transformers.js/v3.8.1/en/custom_usage)。

## 自动积累与设置继承

用户只操作输入辅助开关，无词条确认、问答评价或手工审核流程。

- 设置页保存账号默认值：术语补全、表达建议、本地 NLP、自动积累。
- 会话配置的输入辅助带右侧展开箭头；默认继承全局，逐项覆盖，支持恢复继承。未覆盖项随全局改变。
- 原有浏览器会话偏好在没有服务器覆盖时导入；既有自动学习关闭状态保留。
- 新同步对话中的明确释义和标注术语经过滤直接生效。旧候选从仍可用的来源重新提取，合格自动启用。
- 助手明确建议的专业改写，仅在同会话/执行段/thread/turn 中有唯一可用问题时形成新映射，保留原问题内容，不把整段答案当事实库。
- 来源过期、删除、项目关闭内容同步时清理自动词条；手动保存的旧词条独立保留。
- 自动学习停用期间不积累，更新事件水位，重开不补学停用区间。
- 超过账号 500 条容量时淘汰低使用量的旧自动词条，不要求用户管理；手动词条和删除指纹不自动覆盖。
- 问答与评价面板已移除。原事件与角色作为内部来源，不新增整段正文副本，也不训练模型；旧接口仅保留客户端兼容。

UI 中的“自动”指自动提取、过滤和入库，仍不是任意答案理解。未来扩充自动提取能力必须同时评测误学习、来源隔离和约束保留，不能通过增加用户审核步骤掩盖质量问题。

## 评测与发布

可复现命令（Node 24，首次下载模型）：

```sh
node apps/control-plane/scripts/prepare-writing-model.mjs /absolute/path/to/model
npm --prefix apps/control-plane run build
WRITING_MODEL_PATH=/absolute/path/to/model node apps/control-plane/scripts/eval-writing.mjs
```

`--calibration` 使用首轮 28 条开发探针；默认读取 `writing-holdout.json` 的 35 条自编回归样例。后者曾发现并修复多问题歧义缺陷，因此应视为回归集，不再宣称为从未使用的独立盲测集。新增语料仍需另外准备人工真实数据和独立测试。

当前测量结果及逐条结果见 `writing-assistance-evaluation.json`。应同时报告命中、拒答、错误和分语言指标，不能只报告“输出的都对”。样本少且人为编写，零误建议也不能推导生产环境零错误。延迟不含 600ms 防抖和网络时间。

保留桌面浮层，不让候选数量改变输入框位置。移动端表达候选按实际高度显示，最多四行，收起键盘不丢失；通过浏览器回归检查，仍需要用户真机长期体验反馈。

schema 31 增加账号默认设置、会话覆盖和自动词条来源关联，部署后端和 Web，保留已发布 Agent 字节。升级前备份配置、数据库和 AI 加密密钥，验证迁移、外键、服务就绪、主机连接、页面资源及下载校验和。旧程序不接受 schema 31，回滚须结合升级前备份并处理上线后新增数据。

## 后续验收顺序

1. **中文召回质量**：补充实际口语、错别字、混合输入、否定、多义和跨领域反例，对比至少一种更适合中文的嵌入模型；保持误建议低的同时降低拒答率。
2. **受控改写**：显式保留目标、对象、数值、单位、工具和限制，不把原描述扩成未经证实的原因；必要时澄清。
3. **历史经验闭环**：采用/编辑/发送/反馈分别记录，自动摘要质量过滤和纠正链，按用户/项目检索通过质量过滤的案例，来源删除同步清理。
4. **语料扩展与运营**：以已验证的漏召回和领域需求扩充，建立审核差异、导入校验、回滚和按领域质量报告。
