# 主机互通（SSH）

Linux 或 macOS 主机上已经存在的 SSH 账号与密钥，在面板「主机 → 主机互通」登记后，同一工作区内其他 Linux / macOS 主机上的 Agent 即可 `ssh af-<主机名>` 直接操作该主机。面板不生成、不安装密钥。

## 流程

1. 管理员填写用户名和私钥；地址可留空采用主机上报值，端口默认 22。私钥口令、描述在「更多选项」中填写；可访问主机范围仍明确展示。
   - 名称无需填写，新账号别名根据面板主机名自动生成，例如 B52H → `af-b52h`。字符规范化后无法使用时退回原生主机名，再退回主机 ID；同工作区重名自动追加 `-2`、`-3` 等。保存后别名固定，编辑或主机改名不改变已有连接命令。
   - 公钥和密钥类型无需填写，由服务端从私钥推导；旧 API 的显式名称、类型、公钥参数仍兼容并校验。
   - 私钥与口令以 AES-256-GCM 加密存储（`ssh-access.key` 位于数据库旁，0600），API 永不回显。
   - OpenSSH 私钥自带公钥；PEM／PKCS8 私钥使用本地密码库提取。支持 ED25519、RSA、ECDSA。加密私钥需要私钥口令，不是 SSH 登录密码。编辑时留空保留原密钥；更换私钥会重新推导类型和公钥。显式密钥不匹配、类型不一致、加密私钥缺口令都会在保存时拒绝。
2. 控制面让**被访问主机**自检（`ssh.request action=inspect`）：账号是否存在、公钥是否在 `authorized_keys`、上报 `/etc/ssh/ssh_host_*_key.pub`、sshd 端口与候选 IP。主机指纹因此经受信通道固定，地址留空时使用上报的 IP。
3. 控制面向每台可访问的 Linux 主机下发**完整期望状态**（`action=sync`）。主机连接服务：
   - 写入 `~/.ssh/agentfleet/`：`config`、`known_hosts`（按 `HostKeyAlias` 固定）、`keys/<别名>`（0600，带口令的私钥会去掉口令，因为 Agent 无法交互输入）、`HOSTS.md`、`state.json`；
   - 在 `~/.ssh/config` 顶部插入一行带标记的 `Include`；
   - 带口令的私钥通过 `SSH_ASKPASS` 辅助脚本与子进程环境变量解锁，口令不出现在命令行参数中（命令行对本机所有用户可见，环境变量仅同用户和 root 可读）；
   - 用 `ssh-keygen -y` 核对私钥与公钥，逐账号回报结果；
   - 期望状态为空时删除托管目录和 `Include`。
   主机重连完成对账、账号增删改、主机移除时都会重新下发。
4. Agent 感知：Claude 会话通过 `systemPrompt.append`、Codex 新线程通过 `developerInstructions` 注入可访问主机列表；其他 Agent 可读取 `~/.ssh/agentfleet/HOSTS.md`。
5. 「测试连接」让每台可访问主机执行 `ssh -o BatchMode=yes af-<名称> true`。

## 连接方式与互通矩阵

- **连接方式**：每个账号选「直连」或「经跳板机」。跳板机必须是另一台已经登记了**直连**账号的主机；不允许多级跳转（作为跳板的主机本身必须直连）。主机端写入 `ProxyJump af-<跳板别名>`，实际经过跳板机转发。若跳板账号对某台源主机不可用（未授权、已停用、未安装），该源主机**不会拿到**这个账号，而不是退回直连去尝试。跳板主机自身连接目标时直接连接。
- **虚拟网络（Tailscale、WireGuard、ZeroTier 等）**：面板不管理隧道，只识别。自检时按网卡名和地址段（如 100.64.0.0/10）把候选地址标为「局域网 / 公网 / 虚拟网络」，在编辑账号时可从候选地址中选择填入。主机之间不在同一网络时，填写虚拟网络地址即可。
- **互通矩阵**：行是被访问的账号，列是发起连接的主机，状态来自真实的连接测试（直连 ✓ / 经跳板 ✓ / 失败 / 未测试），并说明某个主机没有拿到账号的原因（账号停用、未授权该主机、没有可用地址、跳板机账号不可用、需更新连接服务、系统不支持）。「测试全部」依次测试每个账号。账号路径、地址、端口或密钥变化后，旧的测试结果自动作废。
- **macOS**：主机自检用目录服务（`dscl`）查询用户和家目录，并探测 sshd 是否在监听；macOS 默认未开启「远程登录」，Agent 无法代为开启，界面会提示在「系统设置 → 通用 → 共享」中打开。
- 路由取值 `auto`、`relay` 已在数据库中预留，用于后续的面板中转，当前接口会拒绝。

## 面板中转（主机之间连不通时）

默认关闭，按工作区由平台管理员在「主机 → 主机互通 → 面板中转」开启。账号的连接方式选「仅经面板中转」，或「自动：直连优先，不通时经面板中转」。

**工作方式。** 源主机的 `ssh` 通过 `ProxyCommand` 运行一个很小的程序（`ssh-proxy-cli.js`，启动约 0.04 秒），它连到本机 Agent 的私有套接字（`~/.ssh/agentfleet/relay.sock`，0600）；Agent 经现有的出站 WebSocket 请求面板；面板校验后通知目标主机，目标主机的 Agent **只连接本机 `127.0.0.1` 上的 sshd**（端口取自它自己的 sshd 配置），然后双方经面板转发字节。SSH 仍是端到端加密，面板看不到内容；帧里从不出现地址或端口，面板也只转发它校验过的字段。「自动」时 `ssh-proxy` 先用 3 秒尝试真实地址，不通再走中转。

**安全规则。**
- 目标主机的指纹必须已固定，否则不下发：面板处在中间位置，只有固定的指纹能让 `ssh` 发现篡改。
- 每次 `relay.connect` 都在面板按「同步给该主机的同一份计划」校验：开关已开、账号启用、该主机在授权范围内、双方连接服务都支持中转、指纹已固定。账号被删除、改为直连、停用、授权范围收窄、主机被吊销、开关关闭时，已打开的流立即关闭。
- 只有流的两端主机能使用它，并且必须是各自**当前**的连接；被替换的旧连接发出的帧一律忽略。
- 限额：每台源主机 8 条、每台目标主机 16 条、每个工作区 24 条；每台主机每分钟最多 30 次建立；单流每秒 32 MiB（防滥用，不是限速）；空闲 30 分钟、存活 8 小时后关闭。
- 记录：每条流的建立与结束写入审计，只含源、目标、账号、字节数、时长和结束原因，没有内容。
- 目标主机返回的文字在显示到用户终端之前会去掉控制字符。

**断线续传。** 主机到面板的 WebSocket 会断（实测平均每 1–2 小时一次，Cloudflare 重启时也会），所以两端各自保留带序号的未确认数据（窗口 256 KiB）。连接断开后流被挂起 60 秒；主机重连并对账后互发 `relay.resume`，对方重发对方没收到的部分，SSH 会话感觉不到。超过 60 秒没回来，或面板重启（面板不保存流状态），流被关闭，两端清理。

**部署。** 面板发布器会把活动中的中转流和语音通话一样计为"需要等待"：有活动流就推迟（退出码 75），不会强行断开。进程异常退出遗留的记录超过 5 分钟没刷新即不再计入。

**速度与适用范围。** 中转是为了在连不通时执行命令，不是传文件的通道。吞吐受「窗口 256 KiB ÷ 往返延迟」限制：往返 50 ms 约 5 MiB/s，150 ms 约 1.7 MiB/s；回环实测一次命令约 0.5 秒、32 MiB 约 29 MiB/s（没有网络延迟）。

**风险。** 中转流量经过面板域名。若该域名使用了 CDN 或代理服务，请确认其服务条款允许转发 SSH 数据（例如 Cloudflare 的服务条款限制清单里有「不得用该服务提供虚拟专用网络或类似代理服务」，对 WebSocket 没有明确说明）；这是启用前需要自己判断的合规问题，面板无法替你确认。若想让中转绕开它，可以为中转单独配置一个不经代理的域名（后续支持）。

## 约束与已知限制

- 仅 Linux 和 macOS（`machines.platform` 为 linux/ubuntu/darwin）；Windows 暂不支持。旧版连接服务不上报 `capabilities.sshAccess`，不会收到任何 SSH 帧；不上报 `capabilities.sshRoutes` 的主机不会收到经跳板的账号。
- 主机指纹未上报时退回 `StrictHostKeyChecking accept-new`，并在界面标注「指纹未固定」。
- Agent 提示词与 `HOSTS.md` 按各主机真实状态标注「主机指纹已固定 / 未固定」，不再统一声称已校验。
- `verify`、`test` 与保存、删除一样需要平台管理员，并按用户限流（verify 20 次/分钟，test 10 次/分钟）。
- Codex 默认沙箱禁止网络，`ssh` 需经审批提升执行。
- 风险：任一可访问主机被攻破即可登录目标账号。请使用专用非 root 账号，并用「可访问主机」收窄范围。
